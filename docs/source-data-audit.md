## 1. Chaw Cher Product Master v3

- ไฟล์: `product_master_v3.xlsx` (Drive id `1v3dUdgJG6Au-A_k3iHksAeT2Zt0QhsQ7`)
- โครงสร้าง 4 ชีท: README / Master Data / Website Export / Summary
- Website Export ดึงค่าจาก Master Data ด้วยสูตร (แก้ที่เดียว)

คอลัมน์ใน Master Data แบ่งเป็น 4 กลุ่ม:

| กลุ่ม | คอลัมน์ที่พบ |
|---|---|
| Product identity | Category, Collection Name, Product name (EN), Parent group key, Existing product code, Existing NNSKU#, **New parent SKU (ว่าง รอทีมกรอก)**, **New variant SKU (ว่าง รอทีมกรอก)**, Wood, Wood Colour, ... |
| Pricing | Regular price = "Retail Price (VAT)" / Promotion price (ว่าง ให้กรอกเฉพาะตอนมีแคมเปญ) |
| Cost & Margin | CoGs, ค่าขนส่ง, commission NN, ต้นทุนรวม, กำไร, %กำไร, MKT+Oth, HR, NI — **หัวสีแดงเข้ม จำกัดสิทธิ์ ไม่ส่งออกทีมเว็บ** |

ข้อสังเกตที่ตรงกับโจทย์:
- ไฟล์นี้ **แยก parent/variant ไว้แล้วในความคิด** (มีคอลัมน์ New parent SKU กับ New variant SKU)
  แต่ยังว่างทั้งคู่ → ยังไม่มีใครกรอก
- แถวสีแดงอ่อน = ยังไม่มีโค้ดสินค้าจริง (ว่าง หรือเป็น `xxxx`) — ตรงกับตัวเลข 548 แถว
- มีคอลัมน์ `Existing NNSKU#` = รหัสฝั่ง NocNoc → มีรหัสจากช่องทางขายภายนอกปนอยู่ด้วย
- `Parent group key` = Category + Collection Name เป็นแค่ตัวช่วยจัดกลุ่ม ไม่ใช่ SKU จริง

## 2. Chaw Cher Stock

- ไฟล์: Google Sheet (id `15qf7h1QKUQbYRZxUh2ddVb_f0HUozNTCjxBCXy3tkEA`) ขนาด ~8.2 MB
- ชีทที่เห็น: `CHAW CHER STOCK 2-9-69`

คอลัมน์:

```
(เลขลำดับ), Product Name, Brand, Categories, Material, Color, ขนาด,
สินค้าพร้อมขาย, คงเหลือ, รอส่งลูกค้า,
ASE-เพื่อขาย, ชอบใจ Studio, ฌ เฌอ โฮม, ของงานแสดง ASE, ของเสีย(ASE),
ฌ เฌอ Showroom, Showroom (Defected), BLS, NEWLOT,
หมายเหตุ, Landing Cost, Inventory Value
```

**ข้อค้นพบสำคัญที่ขัดกับโจทย์ที่ Bay สั่งไว้:**

โจทย์บอกว่า "สต็อกนับเป็นตัว (per unit) แต่ละตัวมีรหัสของตัวเอง"
แต่ไฟล์นี้เก็บเป็น **จำนวนนับรวมต่อช่อง (quantity per bucket)** ไม่ใช่ต่อตัว
เช่น "สินค้าพร้อมขาย = 9" ไม่ได้บอกว่าเป็นตัวไหน 9 ตัว

→ แปลว่า **ข้อมูลต้นฉบับไม่มีตัวตนรายตัว (unit identity) ให้ย้ายเข้าระบบใหม่เลย**
ต้องตัดสินใจว่าจะสร้างรหัสรายตัวขึ้นใหม่ตอน migrate ยังไง (เป็นคำถามข้อหนึ่ง)

ข้อสังเกตอื่น:
- ชื่อสินค้าฝังทั้งขนาดและรหัสเดิมไว้ในช่องเดียว เช่น `Andaman (1580*470*760) CHA-02`
  → มีระบบรหัสเดิมอยู่แล้ว (CHA-02, BIL-02, ...) คนละแบบกับ SKU 8 หลักที่จะทำใหม่
- คอลัมน์ `Brand` มีค่าเช่น `HOF` → ในไฟล์เดียวมีหลายแบรนด์ปนกัน
- ช่องตำแหน่ง/เจ้าของของมี 9 ช่อง (ASE-เพื่อขาย, ชอบใจ Studio, ฌ เฌอ โฮม, ของงานแสดง ASE,
  ของเสีย(ASE), ฌ เฌอ Showroom, Showroom (Defected), BLS, NEWLOT)
  → ปนกันระหว่าง "สถานที่", "นิติบุคคลเจ้าของ", และ "สภาพของ"
- ตำหนิบันทึกเป็นข้อความอิสระในช่องจำนวน เช่น `1 = สีซีด`, `2 =สีต่าง`,
  `1=สีหยด`, `1 = ถลอกขอบล่าง` → ข้อมูลสภาพรายตัวมีอยู่จริง แต่อยู่ในรูปที่เครื่องอ่านไม่ได้
- มี `Landing Cost` และ `Inventory Value` อยู่ในไฟล์เดียวกับข้อมูลที่ทีมคลังใช้
  → ขัดกับกฎ "ต้นทุนจำกัดสิทธิ์เฉพาะเจ้าของ"

## 3. Chaw Cher Order Tracking

- ไฟล์: Google Sheet (id `1y9ROPiZHSxFiJSw0oNTrC9xPtmX0RlZu-6vZWPDsxYc`)
- **10 ชีท, 3,763 แถวที่มีข้อมูล** (ตัวเลขจากบันทึกการทำความสะอาดเมื่อ 2026-09-16)
- ชีทที่เห็นชื่อ `order2026` → เดาได้ว่าแบ่งชีทตามปี และมีชีท `Delivery` แยกอีกต่างหาก

คอลัมน์:

```
PO, w/o, ใบกำกับ/ใบชมพู, วันที่สั่งซื้อ, เลขที่ใบสั่งซื้อ (NocNoc),
ชื่อลูกค้า, E-MAIL, LINE, FACEBOOK, IG, เบอร์ติดต่อ,
ที่อยู่เปิดใบกำกับ, ที่อยู่จัดส่ง,
รายการ, Total Sales,
NocNoc, มีค่าบริการการชำระเงิน, order ผ่าน ASE, บัตรเครดิต, ASE, SCB/TTB, Balance,
กำหนดส่งของ, ส่งโดย, ค่าขนส่ง, commission (10%),
วันที่ต้องการให้ผลิตเสร็จ, รายได้ (without VAT), ต้นทุน
```

**ข้อค้นพบสำคัญ:**

1. **หนึ่งออเดอร์กินหลายแถว** — แถวแรกมีเลข PO แล้วแถวถัดไปเว้น PO ว่างไว้
   แต่ใส่รายการสินค้าเพิ่ม → ต้องประกอบ order ↔ line item กลับคืนตอน migrate
2. **รายการสินค้าเป็นข้อความอิสระ มีจำนวนฝังอยู่ในข้อความ**
   เช่น `EMU CHAIR Ash-Walnut /เบาะหนัง Sm-Wheat x 8pcs`
   → ไม่ผูกกับโค้ดสินค้าใดๆ ต้อง map เข้า SKU ด้วยมือหรือกึ่งอัตโนมัติ
3. **การชำระเงินแตกเป็นหลายคอลัมน์ + มี Balance**
   (NocNoc / บัตรเครดิต / ASE / SCB-TTB / Balance)
   → มีการรับเงินหลายช่องทาง และมีมัดจำ/ยอดค้างชำระจริง
4. **มี `วันที่ต้องการให้ผลิตเสร็จ`** → งานสั่งผลิต (made-to-order) อยู่ในระบบนี้ด้วย
5. **มี `ต้นทุน` และ `commission (10%)` อยู่ในไฟล์เดียวกับที่ทีมขายใช้**
   → ขัดกับกฎ "ต้นทุนจำกัดสิทธิ์เฉพาะเจ้าของ" เหมือนไฟล์ Stock
6. เลข PO ขึ้นต้น `BLS` ซึ่งเป็นชื่อเดียวกับคอลัมน์หนึ่งในไฟล์ Stock
   → `BLS` น่าจะเป็นช่องทาง/คู่ค้า ไม่ใช่แค่ตำแหน่งเก็บของ (ต้องให้ Bay ยืนยัน)

## สรุปสิ่งที่ข้อมูลต้นฉบับ "ไม่มี" และต้องตัดสินใจก่อน migrate

1. **ไม่มีตัวตนรายตัวของสต็อก** — Stock เก็บเป็นจำนวนนับ ไม่ใช่รายตัว
2. **ไม่มี SKU ที่ใช้ได้จริง 548 แถว** — และคอลัมน์ parent/variant SKU ยังว่างทั้งไฟล์
3. **ไม่มีการเชื่อมระหว่างรายการในออเดอร์กับสินค้า** — รายการเป็นข้อความอิสระ
4. **ไม่มีการแยกลูกค้าออกจากออเดอร์** — ลูกค้าเดิมสั่งซ้ำ ข้อมูลถูกพิมพ์ซ้ำใหม่
5. **ไม่มี Bill of Materials** — ทั้งที่มีคอลัมน์ "วันที่ต้องการให้ผลิตเสร็จ" อยู่แล้ว
6. **ต้นทุนปนอยู่ในไฟล์ที่ทีมงานใช้** ทั้ง Stock และ Order Tracking
