# สำรวจ branch ที่ยังไม่ได้ merge · พ.ย. 2569

สำรวจ 2026-11-16 · **อ่านอย่างเดียว** ไม่ได้ลบ ไม่ได้แก้ ไม่ได้ merge branch ไหนเลย
เทียบกับ `claude/chaw-cher-os-setup-9k21w6` (ต่อไปเรียก **setup**) ที่ commit `9760e54` (2026-11-16 · 227 commit)

วิธีตรวจ: `git fetch --unshallow` → นับ commit ที่นำ/ตาม → `git diff setup...branch` ดูไฟล์ที่เปลี่ยน → `git merge-tree` ลอง merge ในหน่วยความจำเพื่อหาไฟล์ชน → เทียบเลข migration ซ้ำ
**ไม่ได้ทดสอบ build หรือรัน migration ของ branch ใดเลย** · "ไม่ชน" ในตารางแปลว่า git รวมข้อความได้ ไม่ได้แปลว่าโค้ดทำงาน

เกณฑ์จัดลำดับ = ลำดับความสำคัญของ Bay (`docs/decisions-log.md` O4 · O5): คอนเทนต์ก่อน → เอาคอนเทนต์ไปหาเงิน → **พาคนที่ทักแชทมาโชว์รูม** · งานนอกวงจรนี้พักไว้

- ผมเข้า Vercel ไม่ได้ จึง**ยืนยันไม่ได้ 100%** ว่าเป็นเพราะตาม `main` หรือเพราะ deploy ของ setup ล้ม · แต่ผลเหมือนกัน: **งานที่ merge เข้า setup หลัง 10 พ.ย. น่าจะยังไม่ขึ้นเว็บจริง**

สิ่งที่ Bay ต้องเช็ก (ครั้งเดียว):

1. เปิด [หน้าตั้งค่า Environments ของโปรเจกต์ chawcher-os](https://vercel.com/bay8/chawcher-os/settings/environments) → กด **Production** → ดูช่อง **Branch Tracking** ว่าเป็น `main` หรือ `claude/chaw-cher-os-setup-9k21w6`
   - ลิงก์นี้ผมประกอบจากชื่อทีม `bay8` และชื่อโปรเจกต์ ยังไม่ได้ลองเปิด · ถ้าไม่ขึ้น ให้เข้า [หน้ารวมของ Vercel](https://vercel.com/dashboard) → โปรเจกต์ **chawcher-os** → **Settings** → **Environments**
2. ถ่ายหน้าจอส่ง Claude · แล้ว Claude จะเสนอทางเดียวให้เลือก (ตั้งกลับเป็น setup หรือ merge setup เข้า main · `git merge-tree` บอกว่ารวมกันได้ไม่ชน)

จนกว่าจะรู้คำตอบ **ทุกคำว่า "merge" ในตารางข้างล่างหมายถึง merge เข้า setup** และยังไม่รับประกันว่าจะขึ้นเว็บจริง

### 2 · "no merge base" ที่เคยเห็น ไม่จริง

เครื่องของ session ดึง repo มาแบบตื้น (shallow · 50 commit ล่าสุด) จึงมองไม่เห็นประวัติร่วมของ branch เก่า 4 ตัว (`beautiful-thompson` · `busy-babbage` · `exciting-curie` · `wizardly-clarke`) และนับผิดว่านำอยู่ 77–83 commit
ดึงประวัติเต็มแล้ว **ทุก branch มีประวัติร่วมกับ setup** · ตัวเลขในตารางคือตัวเลขจริงหลังดึงเต็ม
ผลที่ตามมา: branch เก่า merge ได้ตามปกติในทางเทคนิค ไม่ต้องยกไฟล์ทีละไฟล์เพราะประวัติขาด · แต่ตัวที่ตามหลัง 150 commit ยังต้องทดสอบใหม่บนโค้ดปัจจุบัน

### 3 · มี branch หนึ่งที่มีตัวเลขต้นทุนและไฟล์ลูกค้า

`claude/affectionate-turing-35qnid` มีไฟล์ BOM (`.xlsx` `.pdf`) ที่ข้อความ commit ระบุว่าใส่ราคาวัสดุและเทียบราคาภายในกับตลาด (ผมไม่ได้เปิดอ่านตัวเลข) และไฟล์แปลนของลูกค้าใน `docs/source/customer/` · ขัดกฎ "ตัวเลขต้นทุนห้ามลง repo" และ "ไม่คัดข้อมูลลูกค้าลง repo" · **ห้าม merge** · ตัว branch อยู่บน GitHub อยู่แล้ว Bay ควรตัดสินว่าจะลบ branch นี้หรือไม่ (ผมไม่ได้แตะ)
