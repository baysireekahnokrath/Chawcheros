# ใครเข้าอะไรได้บ้าง · สรุปเรื่องล็อกอิน

อัปเดต 2026-11-09

---

## ประตูมี 3 แบบเท่านั้น

| แบบ | หน้าไหน | ใครเข้าได้ |
|---|---|---|
| **A · ล็อกอิน** | ทุกหน้าในระบบ | พนักงานที่มีบัญชี + มีสิทธิ์ตรงกับโมดูลนั้น |
| **B · PIN ไม่ต้องล็อกอิน** | `/pos` · `/phoenix` | ใครก็ได้ที่รู้ PIN |
| **C · เปิดโล่ง แต่ไม่มีข้อมูล** | `/login` · `/reset` | ใครก็ได้ · หน้าเปล่า ไม่มีข้อมูลอะไรเลย |

จำง่าย ๆ · **ถ้าไม่ใช่ `/pos` `/phoenix` `/login` `/reset` แปลว่าต้องล็อกอิน**

## แบบ A · หน้าที่ต้องล็อกอิน

สินค้า · ใบราคา · Data Sheet · ลูกค้า · ออเดอร์ · คลัง · คอนเทนต์ ·
การตลาด · LINE · ตั้งค่า POS · ตั้งค่าระบบ — ทั้งหมดอยู่กลุ่มนี้

ไม่ล็อกอินแล้วพิมพ์ URL เข้ามาตรง ๆ จะถูกเด้งไปหน้า `/login`
แล้วพอล็อกอินเสร็จ พากลับไปหน้าที่ตั้งใจจะไปให้เอง

### ล็อกอินแล้วไม่ได้แปลว่าเห็นทุกอย่าง

กันสองชั้น · ต่อให้เปิดหน้าได้ ถ้าไม่มีสิทธิ์ก็ไม่มีข้อมูลขึ้นมา

| ชั้น | อยู่ตรงไหน | ทำอะไร |
|---|---|---|
| 1 · ประตูหน้า | `web/src/middleware.ts` | ไม่มี session → เด้งไป `/login` |
| 2 · ประตูข้อมูล | RLS ใน Postgres · เปิดไว้ **91 ตาราง** | ไม่มีสิทธิ์ → คิวรีคืนศูนย์แถว |

ชั้นที่ 2 สำคัญกว่า · ต่อให้มีใครเจาะหน้าเว็บได้ ฐานข้อมูลก็ยังไม่ยอมคืนข้อมูล

### สิทธิ์ 13 อย่าง · ไม่ใช่ "ตำแหน่ง" แต่เป็น "ความสามารถ"

ออกแบบแบบนี้เพราะที่นี่บางคนทำหลายแผนก บางแผนกมีคนเดียว
คนหนึ่งถือได้หลายอย่างพร้อมกัน ประกอบเอาเองตามหน้างาน

```
products.read    ดูสินค้า ราคา ผ้า
products.write   เพิ่ม/แก้สินค้า ออก SKU
stock.read       ดูว่าของอยู่ไหน
stock.write      สแกน ย้ายของ ตำหนิ ยืม-คืน
purchase.write   ใบสั่งซื้อ รับของเข้า สร้างล็อต
sales.write      lead นัด ใบเสนอราคา ออเดอร์
cs.write         บันทึกข้อสรุปการคุย เคส
marketing.write  แคมเปญ โปรโมชัน
design.write     งานกราฟิก
delivery.write   นัดส่ง ติดตาม
finance.write    ยืนยันเงินเข้า ค่าใช้จ่าย
cost.read        🔒 ต้นทุนและกำไร — เจ้าของเท่านั้น
admin            จัดการผู้ใช้ อนุมัติ
```

**เมนูหน้าแรกสร้างตัวเองจากสิทธิ์** · โมดูลไหนที่คนนั้นไม่มีสิทธิ์ ไอคอนจะไม่ขึ้นเลย
ไม่ใช่ขึ้นแล้วกดไม่ได้ · เห็นเท่าที่ทำได้ จะได้ไม่ต้องเดา

**ต้นทุนแยกขาด** · อยู่คนละ schema (`cost`) และบังคับที่ฐานข้อมูลว่าต้องมี `cost.read`
ไม่ได้กันแค่ที่หน้าจอ · ตอนนี้เจ้าของคนเดียวที่ถือ

## แบบ B · PIN ไม่ต้องล็อกอิน

ทั้งสองหน้าใช้กลไกเดียวกัน แต่ **PIN คนละตัว เปลี่ยนอันหนึ่งไม่กระทบอีกอัน**

| | `/pos` ขายหน้าบูธ | `/phoenix` จัดชุดฟีนิกซ์ |
|---|---|---|
| ทำอะไรได้ | บันทึกบิล ดูยอดขาย | ดูใบราคาฟีนิกซ์ จัดชุด ได้แบบแปลน |
| ประตู | `pos.check_pin` / `pos.record_sale` | `pricing.phoenix_sheet(pin)` |
| คืนอะไร | เฉพาะของ POS | เฉพาะแถวฟีนิกซ์ · **ไม่มีต้นทุนสักช่อง** |
| ใส่ PIN บ่อยแค่ไหน | ครั้งเดียวต่อเครื่อง | ครั้งเดียวต่อเครื่อง |
| ตั้ง/เปลี่ยน PIN | `select pos.set_pin('...')` | `select pricing.set_phx_pin('...')` |

ทำไมปลอดภัยทั้งที่ไม่ต้องล็อกอิน

- ตารางยังปิดสนิทเหมือนเดิม คนที่ไม่ล็อกอินแตะตารางตรง ๆ ไม่ได้สักตาราง
- เข้าได้ทางฟังก์ชันที่กำหนดไว้เท่านั้น · PIN ผิดคือไม่คืนข้อมูลเลย ไม่ใช่คืนน้อยลง
- ฟังก์ชันเลือกไว้แล้วว่าคืนอะไรบ้าง · ขอเพิ่มไม่ได้ ไม่ว่าจะส่งอะไรเข้าไป
- PIN เก็บเป็น hash ไม่ได้เก็บตัวรหัส · อ่านย้อนไม่ได้แม้แต่คนทำระบบ
- คำสั่งเปลี่ยน PIN เรียกได้เฉพาะเจ้าของฐานข้อมูล คือที่หน้า SQL Editor

### เรื่องที่ยังขัดใจอยู่

คนที่ล็อกอินอยู่แล้ว กดเข้า `/phoenix` จากเมนูหน้าแรก **ยังต้องใส่ PIN อีกรอบ**
เพราะหน้านั้นอ่านข้อมูลทางประตู PIN อย่างเดียว ไม่ได้ดู session
แก้ได้ถ้าอยากให้คนที่ล็อกอินแล้วผ่านเลย · ยังไม่ได้ทำ
