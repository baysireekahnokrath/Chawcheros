# วิธีทำงานกัน — ทีละด่าน ไม่รวดเดียว

ตกลงกัน 2026-09-23 หลังจาก Bay ทักว่าวิธีเดิมเปลืองและต้องแก้ย้อนหลังบ่อย

---

## ปัญหาของวิธีเดิม

ผมทำ **คุย → สร้าง → deploy** รวดเดียวในเทิร์นเดียว ผลคือ

- ความเข้าใจผิดทุกจุดกลายเป็นงานแก้**บนของจริง** ซึ่งแพงที่สุด
- token หมดเร็ว เพราะสร้างจริงกินมากกว่าคุยหลายสิบเท่า
- Bay เห็นของครั้งแรกตอนมันขึ้น production ไปแล้ว สายเกินจะบอกว่า "ไม่ใช่แบบนี้"

ตัวอย่างจริงที่เกิดขึ้น — ทั้งสามอันเจอหลังขึ้นจริงแล้วทั้งนั้น

| เจออะไร | ถ้ามี mockup ก่อนจะเจอตอนไหน |
|---|---|
| หน้าตรวจเลือกรายตัวไม่ได้ | ด่าน 2 (ตอนเขียน requirement) |
| ตารางกลืนชนิดไม้จนแยกของไม่ออก | ด่าน 3 (ตอนกด mockup) |
| อยากได้ checkbox ไม่ใช่ปุ่มต่อกลุ่ม | ด่าน 3 |

## 4 ด่านต่อ 1 โมดูล — ห้ามข้าม

| ด่าน | ได้อะไรออกมา | เก็บไว้ที่ไหน | Bay ทำอะไร |
|---|---|---|---|
| **1 · Workflow** | ใครทำอะไร ส่งต่อให้ใคร จบตรงไหน | `docs/modules/<ชื่อ>/1-workflow.md` | อ่าน แก้ ยืนยัน |
| **2 · Requirement** | รายการ "ต้องทำอะไรได้บ้าง" เป็นข้อๆ มีเลขกำกับ | `docs/modules/<ชื่อ>/2-requirements.md` | ตัด/เพิ่ม/ติ๊กผ่าน |
| **3 · Mockup** | หน้าเว็บกดได้จริง ข้อมูลปลอม ไม่ต่อฐานข้อมูล | `docs/modules/<ชื่อ>/mockup.html` | เปิดบนมือถือ กดเล่น บอกจุดที่ผิด |
| **4 · ของจริง** | ต่อฐานข้อมูล + ทดสอบ + ขึ้น production | `supabase/` + `web/` | ใช้งานจริง |

**ด่านหนึ่งไม่ผ่าน ห้ามขึ้นด่านถัดไป** — โดยเฉพาะ 3 → 4

## กฎประหยัด token

1. **เอกสารอยู่ในไฟล์ ไม่ใช่ในแชท**
   Bay อ่านไฟล์แล้วคอมเมนต์เป็นข้อ เช่น *"ข้อ 4 ตัด ข้อ 7 เปลี่ยนเป็น..."*
   ผมแก้ไฟล์ ไม่ต้องยกเนื้อหาทั้งก้อนมาเล่าซ้ำในแชท

2. **1 session = 1 ด่าน**
   จบด่านแล้วเปิด session ใหม่ ไฟล์ในrepo คือความทรงจำ ไม่ใช่ประวัติแชท

3. **Mockup เป็น HTML ไฟล์เดียว**
   ไม่มี build ไม่มี deploy ไม่มีฐานข้อมูล แก้แล้วเห็นทันที แก้กี่รอบก็ได้

4. **ของที่ตัดสินใจแล้ว อยู่ใน `docs/decisions-log.md`**
   ผมไม่ถามซ้ำ Bay ไม่ต้องตอบซ้ำ ถ้าผมถามซ้ำแปลว่าผมผิด

5. **ไม่ยก SQL หรือโค้ดยาวๆ มาแปะในแชท**
   เขียนลงไฟล์แล้วบอกว่าอยู่ไฟล์ไหน

## ทำไมถึงประหยัดจริง

| ด่าน | ต้นทุนโดยเปรียบเทียบ | แก้กี่รอบก็ได้ไหม |
|---|---|---|
| 1 Workflow | ต่ำมาก | ได้ |
| 2 Requirement | ต่ำ | ได้ |
| 3 Mockup | ปานกลาง | ได้ |
| 4 ของจริง | **สูงที่สุด** | **แพงทุกรอบ** |

ความเข้าใจผิดที่จับได้ในด่าน 1-3 แทบไม่มีต้นทุน
ความเข้าใจผิดเดียวกันที่จับได้ในด่าน 4 ต้องแก้ทั้งฐานข้อมูล หน้าเว็บ และ deploy ใหม่
