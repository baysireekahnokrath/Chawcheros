## 4 รอบ · ต่อจากเฟส 1 (R1–R6)

| รอบ | ได้อะไร | ข้อ requirement | ต้องได้จาก Bay ก่อนทดสอบ |
|---|---|---|---|
| **R7 · ส่งเข้า WordPress** | ปุ่มส่งบล็อกเป็น Draft (Yoast · ภาพปก · หมวด) · ส่งซ้ำอัปเดต Draft เดิม · เช็ก Publish ทุกชั่วโมงแล้วใส่ลิงก์เอง · ลิงก์แอดมินเว็บ · agent ใส่ UTM ทุกลิงก์ · แท็บ "เชื่อมต่อ" (เริ่มที่ WordPress) | W-01–09 · S-04 · X-01–03 | **P5** ผู้ใช้ Author + Application Password ใส่ Vercel |
| **R8 · Line OA** | ช่อง Line ต่อแบรนด์ · agent เขียนตามคู่มือ Line · ข้อความ+รูป / การ์ดเลื่อน · ตัวอย่างมือถือ · ส่ง/ตั้งเวลา (คนกด + ยืนยัน) · เพดานโควตา · ยอด Line | L-01–09 · L-11 · X-04 | **P3** เปิด Messaging API + token ใส่ Vercel (ต่อแบรนด์) |
| **R9 · ยอด FB + IG** | ดึงยอดทุกชั่วโมง 48 ชม. แล้ววันละครั้ง 30 วัน · แท็บ "ยอด" ในการ์ด · ป้ายเตือนเมื่อดึงไม่ได้ · เก็บยอดแบบไม่ทับ | S-01 S-02 S-06 S-11 S-12 | **P1 P2** สิทธิ์เพจ + Meta app + token |
| **R10 · conversion + หน้าแรก + agent เรียน** | ยอดเว็บจาก GA4 + Search Console · conversion rate ต่อโพสต์ · กล่องหน้าแรก 3 กล่อง · agent สรุปทุกวันจันทร์เสนอเข้าสมุด · แผนเดือนใช้สมุดจากยอด | S-03 S-05 S-07–S-10 | **P4** สิทธิ์อ่าน GA4/SC · **P6** `book_showroom` |

```
R7 WordPress → R8 Line OA → R9 ยอด FB+IG → R10 conversion + หน้าแรก
```

**ทำไมลำดับนี้:** R7 เตรียมง่ายสุดและ UTM ต้องเริ่มก่อน ยอดจะได้จับคู่โพสต์ได้ตั้งแต่วันแรก · R10 ต้องมียอดทุกช่องทางแล้วถึงจะมีอะไรให้สรุป

**ดึงยอดตามเวลา:** ใช้ Vercel Cron เรียก route ภายในทุกชั่วโมง (ไม่ต้องมี server เพิ่ม) · ล็อกด้วย secret ใน env var

## แต่ละรอบทำงานเหมือนเฟส 1

1. ผมเขียน migration + หน้าจอ + ทดสอบ SQL ในเครื่อง
2. push ขึ้น branch → พี่ลองบน preview
3. พี่บอก "Rx ผ่าน" → ผมเปิด PR แล้ว merge ขึ้นเว็บจริง

ถ้าพี่ยังไม่ได้เตรียม P ของรอบนั้น ผมสร้างโค้ดได้ก่อน · ปุ่มจะขึ้น "ยังไม่ต่อ" จนกว่าจะใส่ token
