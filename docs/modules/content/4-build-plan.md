## ทำไมต้องแบ่งรอบ

ด่าน 4 คือต่อฐานข้อมูลจริง ทดสอบ แล้วขึ้น production ซึ่งเป็นด่านที่แพงที่สุด
ถ้าทำรวดเดียวทั้งหมด พี่จะได้เห็นของจริงครั้งแรกตอนเสร็จหมดแล้ว ซึ่งเป็นปัญหาเดิมที่เราเลิกทำ
**แบ่งเป็น 6 รอบ ทุกรอบใช้งานได้จริงเมื่อจบรอบ** พี่ลองใช้ แล้วค่อยไปรอบถัดไป

## ลำดับที่ผมแนะนำ

```
R1 ชิ้นงาน → R2 ตรวจ+แชท → R3 agent → R4 ปฏิทิน → R5 หน้าแรก → R6 แผน+แบรนด์
```

**เหตุผล**
- R1 กับ R2 คือฐาน ทุกอย่างที่เหลือยืนอยู่บนนี้ และจบ R2 ทีมก็ใช้งานจริงได้ครบวงจรแล้ว
- R3 agent เป็นหัวใจที่พี่อยากได้ ขึ้นเป็นลำดับ 3 เพราะต้องมีที่ให้ agent เขียนลง (R1) และที่ให้พี่ตรวจ (R2) ก่อน
- R5 หน้าแรกดึงข้อมูลจากทุกรอบ ทำหลังๆ จะได้ไม่มีกล่องว่าง

**ทางเลือก:** ถ้าอยากเห็น agent เร็วที่สุด สลับเป็น R1 → R3 → R2 ได้ แต่ช่วงนั้นพี่จะตรวจงานด้วยปุ่มอนุมัติแบบเดิมไปก่อน

## แต่ละรอบทำงานยังไง

1. ผมเขียน migration + หน้าจอ + ทดสอบ SQL ในเครื่อง
2. push ขึ้น branch แล้วแจ้งพี่ว่าเสร็จอะไร ทดสอบอะไรไปแล้ว อะไรยังไม่ได้ทดสอบ
3. พี่ลองใช้บน production แล้วบอกจุดที่ผิด
4. แก้จนพี่บอกผ่าน แล้วค่อยไปรอบถัดไป

**1 รอบ = 1 session** ตามกฎประหยัด token · เปิด session ใหม่แล้วพิมพ์ว่า *"เริ่มด่าน 4 รอบ R1 โมดูลคอนเทนต์"* ผมอ่านไฟล์นี้เอง
