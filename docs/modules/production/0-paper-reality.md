## สิ่งที่เอกสารนี้เปิดเผย · และยังไม่มีในแบบที่วางไว้

### 🔴 ช่องว่างที่ 1 · ล็อตวัสดุ และสต็อกวัสดุเป็นตัวเลข

โมดูลวัสดุที่มีอยู่ (`materials`) เก็บ **ชื่อ · สี · ซัพพลายเออร์ · สถานะ มีของ/หมด**
แต่**ไม่มีล็อต และไม่มีจำนวน**

กระดาษใบนี้บอกว่าทั้งสองอย่างคือหัวใจ

> *"ถ้าต่อ lot เราต้องแจ้งลูกค้าว่าสีอาจจะต่างกันได้นิดหน่อย"*

**นี่เป็นกฎธุรกิจจริงที่ถ้าพลาด ลูกค้าร้องเรียน** — หนังคนละล็อตสีเพี้ยน
และเฟอร์นิเจอร์เป็นของที่ลูกค้าซื้อเพิ่มทีหลังเพื่อให้เข้าชุดกัน

### 🔴 ช่องว่างที่ 2 · ชิ้นส่วน (ขา) ไม่ใช่ผ้า

ตาราง `materials` ออกแบบมาสำหรับผ้า/หนัง — มี `width_cm` `rub_test` `composition` `cost_per_m`

**ขา Kamin ⌀5×15 นับเป็นขา ไม่ใช่เมตร** และมีสีของตัวเอง (ธรรมชาติ / พรีเมียม)
ใส่ลงตารางผ้าไม่ได้ ต้องมีที่อยู่ของตัวเอง

### 🔴 ช่องว่างที่ 3 · เวลาผลิตมาตรฐาน · ไม่มีอยู่ที่ไหนเลย

คำถามข้อ 4 ในกระดาษคือ **ขอให้ตั้ง standard ขึ้นมา** — แปลว่าวันนี้ยังไม่มี

> *"ในกรณีลูกค้าต้องการด่วน ขอ standard ว่า Stool ปกติผลิตกี่วัน · 3S ผลิตกี่วัน"*

**นี่คือคำถามที่ลูกค้าถามบ่อยที่สุด และวันนี้ตอบทันทีไม่ได้เลย** ต้องไล่ถามคน

## สิ่งที่ระบบจะเปลี่ยนได้

| วันนี้ | ถ้ามีข้อมูลในระบบ |
|---|---|
| **"BLS เก่าลูกค้าคืออะไร"** → ถามในกลุ่ม → ปรินต์ → เขียนมือ → ตอบกลับ | เปิดหน้าลูกค้า เห็นออเดอร์เก่าทุกใบ พร้อมวัสดุและ**ล็อต**ที่ใช้ → ตอบใน 5 วินาที |
| **"ต่อ lot เดิมได้ไหม"** → ให้พี่หนิงไปเช็ค | ระบบรู้ว่าล็อตเดิมเหลือเท่าไหร่ · ถ้าไม่พอ **เตือนเองว่าต้องแจ้งลูกค้าเรื่องสี** |
| **"ใช้เวลาผลิตกี่วัน"** → ไม่มีใครตอบได้ | เวลาผลิตมาตรฐานต่อหมวด + งานที่คิวอยู่ = วันที่ตอบได้ทันที |
| **เช็คสต็อกขา/หนัง** → เขียนมือในตาราง | หน้าจอเดียว เห็นคงเหลือหลังหักที่จองไว้แล้ว |
| **ถามเรื่องตำหนิ** → ปรินต์ → เขียนมือ → เซ็น | ผูกรูปกับตัวสินค้า ส่งให้คนตอบ บันทึกคำตอบพร้อมคนและวันที่ |

> 📌 ใบที่ 1 น่าสนใจตรงที่ **เขาเลือกใช้กระดาษ ทั้งที่ต้นเรื่องอยู่ใน LINE อยู่แล้ว**
> น่าจะเพราะต้องการ**ลายเซ็นและวันที่** — คือต้องการหลักฐานว่าใครตอบว่าอะไรเมื่อไหร่
> ซึ่ง LINE ให้ไม่ได้ · ระบบให้ได้ และให้ได้ดีกว่ากระดาษ
