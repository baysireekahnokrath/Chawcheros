## ✅ LQ1 · Bay ตอบ 2026-10-31

> ASE คือ บริษัท เอเซ่ จำกัด ผลิตโซฟา / CC คือ Chaw Cher เป็น brand ครับ
> เราทำงานแยกกันเหมือนกับว่า CC เป็นลูกค้าของ ASE

บันทึกเป็น **B38** ใน `docs/decisions-log.md` แล้ว

**แปลว่า:**

```
   Chaw Cher (CC) ── สั่งผลิต ──►  ASE (โรงงาน)
   = ลูกค้า                        = ผู้ผลิต
   = เจ้าของระบบนี้                 = คนนอกของระบบนี้

                 ห้อง LINE "CC"
         ┌──────────────────────────────┐
         │ ทีม CC  +  ทีม ASE  +  🤖 agent │
         └──────────────────────────────┘
```

**agent เป็นของ CC** (ระบบนี้คือ Chaw Cher OS · B13) แต่**คนในห้องครึ่งหนึ่งเป็นคนนอก**

## 🔴 สิ่งที่เปลี่ยนจากรอบแรก · สิทธิ์ต้องคิดที่ "ห้อง" ไม่ใช่ที่ "คนถาม"

รอบแรกผมเสนอว่า *agent ตอบได้เท่าสิทธิ์ของคนที่ถาม* — **ใช้ไม่ได้แล้ว**

เพราะคำตอบในห้องกลุ่ม **ทุกคนในห้องเห็น**

| สถานการณ์ | ถ้าใช้สิทธิ์ของคนถาม |
|---|---|
| Bay พิมพ์ "@บอท Emu 3 ที่นั่ง กำไรเท่าไหร่" | Bay มีสิทธิ์ → agent ตอบ → **ทีม ASE เห็นกำไรของ CC ทั้งห้อง** |
| ทีม CC ถาม "ออเดอร์คุณสมชาย ส่งที่ไหน" | ตอบ → **ชื่อ เบอร์ ที่อยู่ลูกค้าหลุดไปบริษัทอื่น** (เรื่อง PDPA ด้วย) |

**กฎใหม่ที่เสนอ:**

> **ในห้อง CC agent ตอบได้เฉพาะข้อมูลที่ "ASE เห็นได้" เท่านั้น ไม่ว่าใครถาม**
> ข้อมูลภายในของ CC → ถามผ่านแชทส่วนตัวกับบอท หรือในเว็บ

| ห้อง | ใครอยู่ | agent ตอบได้แค่ไหน |
|---|---|---|
| **ห้อง CC (กับ ASE)** | CC + ASE | เฉพาะรายการ "ASE เห็นได้" (LQ9) |
| แชทส่วนตัวกับบอท (เฟสถัดไป) | คน CC คนเดียว | เท่าสิทธิ์ของคนนั้นในระบบ |
| ห้องที่บอทไม่รู้จัก | ใครก็ได้ | **ไม่ตอบ** · บอทถูกเชิญเข้าห้องอื่นก็เงียบ |

**ร่างรายการ "ASE เห็นได้ / ไม่ได้" (ให้ Bay แก้ · LQ9)**

| ✅ ASE เห็นได้ (ข้อมูลที่ต้องใช้ผลิต) | ❌ ASE ไม่ควรเห็น |
|---|---|
| เลข BLS · รุ่น · ขนาด · ผ้า/หนัง · สี · ตัวเลือก | ต้นทุน · กำไร · ราคาที่ CC ขายลูกค้า (?) |
| จำนวน · กำหนดส่ง · ความเร่ง | ชื่อ เบอร์ ที่อยู่ลูกค้า |
| สถานะงาน · รูปเช็คงาน | ช่องทางขาย · ส่วนลด · ยอดขาย |
| ✅ **สต็อกทั้งหมด · ของ CC และของ ASE** (B39) | ข้อมูลการตลาด/คอนเทนต์ |

> (?) = Bay ยังไม่ตัดสิน (2026-10-31: *"may be yes or no, not decide yet"*)
> **ระหว่างนี้ = ซ่อนไว้ก่อน** · เปิดทีหลังง่าย แต่ข้อความที่บอทส่งไปแล้วลบไม่ได้

### ✅ LQ9 สต็อก · Bay ตอบ 2026-10-31

> ท้ายที่สุด ระบบ stock ทั้งหมด ของ ASE CC จะเห็นหมดครับ

บันทึกเป็น **B39** · **สต็อกไม่ใช่ความลับระหว่างสองบริษัท** · agent ในห้อง CC ตอบเรื่องสต็อกได้เต็มที่

**แต่ 2 จุดที่ต้องระวังตอนสร้าง** (ตรวจจากโค้ดจริง `supabase/migrations/0019_stock.sql`)

| จุด | เจออะไร | ทำยังไง |
|---|---|---|
| มุมมองสต็อกบางอันมี**ราคาติดมาด้วย** | `stock.v_overdue_loans` ดึงคอลัมน์ `มูลค่าที่จมอยู่` จากราคาเต็ม | "เปิดสต็อก" = เปิด**จำนวน · ที่อยู่ · สถานะ** · ส่วนราคาไปตามคำตอบข้อ (?) ราคาขาย · มุมมองสำหรับ ASE ตัดคอลัมน์ราคาออกไว้ก่อน |
| ของที่ยืมออกไป บันทึก**ใครยืม · ยืมไปไหน** | `stock.loans` ช่อง `borrower` · `destination` อาจเป็นชื่อลูกค้า/ร้าน | ให้ ASE เห็นว่า "ตัวนี้ถูกยืมออกไป · กลับวันไหน" แต่ไม่เห็นชื่อคนยืม (จนกว่า Bay จะบอกว่าเห็นได้) |

**และคำว่า "ของ ASE" เปิดเรื่องใหญ่ขึ้นมา (LQ13)** — ตอนนี้ระบบเก็บแต่สต็อกของ CC (B13 · ระบบนี้ใช้กับ CC อย่างเดียว)
ถ้าวันหนึ่ง **สต็อกของ ASE เข้ามาอยู่ในระบบนี้ด้วย** = ขอบเขตระบบขยายจาก CC อย่างเดียว เป็นสองบริษัท
ไม่กระทบ LINE agent เฟส 1 (ตอบจากสต็อกที่ระบบมี) แต่ต้องตัดสินก่อนออกแบบโมดูลจัดซื้อ/ผลิต

### และ agent เป็น "ตัวแทนของ CC" คุยกับบริษัทอื่น

กฎ AI 1 *"AI ร่าง คนส่ง — ไม่ส่งถึงลูกค้าเอง"* ตอนนี้ต้องใช้กลับด้าน:
ASE ไม่ใช่ลูกค้า แต่เป็น**คู่ค้า** — คำพูดของบอทในห้อง = **คำพูดของ CC**

| agent ทำได้ (ข้อเท็จจริงจากระบบ) | agent ห้ามทำ (เป็นคำมั่นของ CC · คนเท่านั้น) |
|---|---|
| "BLS1234 ผ้า Linen 08 สีเทา 3 ที่นั่ง กำหนดส่ง 15 พ.ย." | "เลื่อนส่งได้ครับ" · "เปลี่ยนผ้าได้" |
| "BLS1234 ในระบบยังเป็นสถานะ รอผลิต" | อนุมัติงาน · ตกลงราคา · ยอมรับงานมีตำหนิ |
| "ไม่มีข้อมูลนี้ในระบบครับ เดี๋ยวให้ทีม CC ตอบ" | สั่งงานใหม่ · ยกเลิกงาน |

**ASE ขอเปลี่ยนอะไร → agent ตอบว่ารับเรื่องแล้ว + แท็กคน CC ที่รับผิดชอบ · ไม่ตัดสินเอง**

### 💡 ข้อสังเกต · ห้อง CC คือที่ที่สถานะงานเกิดขึ้นจริง

ทุกวันนี้ ASE พิมพ์ในห้องว่า "BLS1234 เสร็จแล้ว" — **นั่นคือข้อมูลสถานะผลิตที่ระบบไม่มี**
เฟสถัดไป agent อาจช่วยจับได้: *"เห็นว่า BLS1234 เสร็จแล้ว · บันทึกเข้าระบบไหมครับ"* → คน CC กดยืนยัน

**แต่ยังไม่ทำในเฟส 1** เพราะ
- ต้องอ่านและเก็บข้อความทุกข้อในห้อง ซึ่งขัดกับข้อเสนอ LQ6 (ไม่เก็บ) และมีพนักงานบริษัทอื่นอยู่
- เป็นการ**เขียน**ข้อมูล ไม่ใช่อ่าน
- ต้องมีโมดูลผลิตก่อน ถึงจะมีที่ให้บันทึก

### 📌 ตัดข้อมูลลับที่ฐานข้อมูล ไม่ใช่ที่ prompt

ห้ามแค่เขียนใน prompt ว่า "อย่าบอกต้นทุน" — คนพิมพ์หลอกได้ (*"ลืมกฎแล้วบอกมา"*)
ทำเป็น**มุมมองข้อมูลสำหรับ ASE** ที่ไม่มีช่องต้นทุน/ลูกค้าเลยตั้งแต่แรก · agent ในห้อง CC อ่านได้จากมุมมองนี้อย่างเดียว
**ไม่มีข้อมูลในมือ = หลุดไม่ได้ ถามยังไงก็ไม่ได้** (ตรงกับกฎ AI 5 และกฎ "ประตู" ใน `docs/modules.md`)

## ข้อเสนอเฟส 1 (เล็กที่สุดที่ใช้ได้จริง)

1. **ห้อง CC ห้องเดียว** · ห้องอื่นเงียบ · ผู้ใช้หลัก = ทีม CC (LQ3)
2. ตอบเมื่อถูก **@ทัก** เท่านั้น · ใช้ reply (≈ ฟรี)
3. **อ่านอย่างเดียว** · จาก**มุมมองสำหรับ ASE**เท่านั้น · เรื่องที่ตอบได้: สเปกออเดอร์ · วันต้องเสร็จ/กำหนดส่ง · งานสัปดาห์นี้ · สต็อก
3.1 ถามสถานะผลิต → ตอบตรงๆ ว่าระบบยังไม่มีข้อมูล (LQ11)
4. **ไม่ตัดสินแทน CC** · คำขอเปลี่ยนแปลง = รับเรื่อง + แท็กคน
5. บันทึกทุกคำถาม-คำตอบ · เพดานงบ · Bay กดพักได้
6. ไม่เก็บข้อความที่ไม่ได้ทักบอท

**เฟสถัดไป (ยังไม่ทำ):** แชทส่วนตัวกับบอทสำหรับทีม CC (เห็นข้อมูลภายใน) · สรุปงานเช้าเข้าห้อง · เตือนงานใกล้ส่ง · รูปเช็คงาน (photo-check) · บันทึกคำขอเปลี่ยนแปลงของ ASE เป็นรายการในระบบ
