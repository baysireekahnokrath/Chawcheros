บันทึก 2026-10-06 · **ยังไม่สร้าง · อยู่ระหว่างคุย**
Bay สั่งชัดว่า *"อย่าเพิ่งไปสร้างอะไรจนกว่าผมจะบอกให้สร้าง"*

## 2. ★ สิ่งนี้ไม่ใช่แคมเปญ CSR — มันคือสะพานที่หายไป

เอกสารออกแบบของ Bay เองเขียนว่าวงจรต้องปิดครบ และช่วงสุดท้าย
*"ประวัติลูกค้า → 12-24 เดือน วนกลับหาการตลาด"* คือช่วงที่ขาด

และเราเคยสรุปกันไว้แล้วว่า **สมาชิก Line OA 7,000 คน ไม่ใช่ลูกค้า 7,000 คน**
เพราะมีแค่ user ID ไม่มีเบอร์ ไม่มีอีเมล ทำอะไรต่อไม่ได้

ปัญหาที่แท้จริงของการขายเฟอร์นิเจอร์คือ **ขายออฟไลน์แล้วไม่เหลือร่องรอยดิจิทัล**
ไม่รู้ว่าโฆษณาตัวไหนทำให้เขามา ไม่มีช่องทางติดต่อที่เขายินยอม ไม่มีเหตุผลจะทักอีก

**หน้านี้แก้ทั้งสามเรื่องพร้อมกัน** และแก้โดยที่ลูกค้า**เต็มใจกรอกเอง**
เพราะเขาได้อะไรกลับไปจริงๆ ไม่ใช่แบบฟอร์มขอข้อมูลเปล่าๆ

นี่คือเหตุผลที่ควรทำ — ไม่ใช่เพราะมันดูดีเรื่องสิ่งแวดล้อม

## 3. ตอบข้อ 3 · conversion ทำได้ไหม → **ได้ และดีกว่าที่คิด**

Bay อาจกำลังรวมสองเรื่องที่ต่างกันมากไว้ด้วยกัน

### แบบที่ 1 · Pixel บนหน้าเว็บ (ที่ Bay พูดถึงในข้อ 6)

ยิงได้ แต่**อ่อน** เพราะมันรู้แค่ "มีคนเข้าหน้านี้"
การซื้อเกิดไปแล้วเมื่อสองสัปดาห์ก่อนที่โชว์รูม pixel ไม่รู้เรื่องนั้นเลย
ประโยชน์จริงคือ**สร้าง audience ไว้ยิงโฆษณาซ้ำ** กับวัดว่ามีคนกรอกกี่คน

### แบบที่ 2 · Offline Conversion API ← **อันนี้คือของจริง**

ทั้ง Meta และ Google มีช่องทางนี้อยู่แล้ว ทำมาเพื่อเคสนี้โดยเฉพาะ

- Meta · Conversions API (offline event)
- Google · Offline Conversion Import

วิธีทำงาน: ส่ง **อีเมลหรือเบอร์ที่เข้ารหัสแล้ว + มูลค่าที่ซื้อจริง + วันที่ซื้อ** ขึ้นไป
แพลตฟอร์มจะจับคู่กลับไปหาคนที่เคยเห็นหรือคลิกโฆษณาเมื่อหลายสัปดาห์ก่อน

**ผลคือ Meta/Google จะเรียนรู้ว่าโฆษณาตัวไหนทำให้เกิดยอดขายเฟอร์นิเจอร์จริง
ไม่ใช่แค่โฆษณาตัวไหนมีคนกดเยอะ** ซึ่งต่างกันมากเมื่อของราคาหลักหมื่นถึงหลักแสน

> **ของที่ขาดคือ "อีเมลหรือเบอร์ที่ลูกค้ายินยอมให้ใช้"**
> ซึ่งหน้าต้นไม้นี่แหละคือข้ออ้างที่ดีที่สุดในการขอ — ลูกค้าให้เพราะอยากได้ใบรับรองต้นไม้
> ไม่ใช่เพราะเราขอเฉยๆ

### ⚠️ PDPA

ส่งข้อมูลลูกค้า (ถึงจะเข้ารหัสแล้ว) ไปให้ Meta/Google ต้องมีคำยินยอม
ต้องมี checkbox ที่เขียนชัดว่าเอาไปทำอะไร · ทำตอนนี้ถูกและง่าย แก้ทีหลังแพงและเสียชื่อ

## 4. ★ ข้อ 7-8 มีอยู่ในระบบแล้ว

ตอนทำโมดูลคลัง Bay สั่งไว้ว่า
*"serial number ใช้กับทุกสินค้าครับ เพื่อที่จะได้ track back ได้ว่าสินค้าตัวนี้
ผลิตที่ไหน วันไหน ใครผลิตส่วนไหนบ้าง"*

ผมจึงใส่ช่องพวกนี้ไว้ใน `stock.units` ตั้งแต่ตอนนั้นแล้ว

| ช่อง | เก็บอะไร | สถานะ |
|---|---|---|
| `unit_code` | รหัสตัว U0000042 | ✅ ใช้งานอยู่ |
| `serial_no` | เลขซีเรียลจริงบนตัวสินค้า | ✅ มีช่องแล้ว · ยังว่าง |
| `made_at` | ผลิตที่ไหน | ✅ มีช่องแล้ว · ยังว่าง |
| `made_on` | ผลิตวันไหน | ✅ มีช่องแล้ว · ยังว่าง |
| `made_by` | ใครผลิตส่วนไหน | ✅ มีช่องแล้ว · ยังว่าง |

**แปลว่าข้อ 7 กับ 8 ไม่ต้องสร้างใหม่ แค่เติมข้อมูลเข้าไป**
ของที่ยังไม่มีคือ **ตารางต้นไม้** กับ **การผูกต้นไม้เข้ากับตัวโซฟา**

## 5. ⚠️ ข้อ 4 · ดึงจาก PO มีปัญหาที่ต้องรู้ก่อน

ดูไฟล์ PO แล้วพบว่า

- **1 PO = 1 แท็บ** มีราว 60 แท็บ (3225, 3221, 3219 … BLS2226, 2756)
- แต่ละแท็บเป็น**ฟอร์มที่ merge เซลล์** ไม่ใช่ตาราง
- ตัวอ่านดึงค่าในเซลล์ออกมาไม่ได้เลย เพราะโครงเป็นแบบกระดาษ ไม่ใช่แบบข้อมูล

**ผลคือการดึง SKU กับมูลค่าอัตโนมัติจะเปราะมาก** ถ้าใครเลื่อนแถวหรือ merge เพิ่ม มันพังเงียบๆ
และยิ่งเพิ่มแท็บไปเรื่อยๆ วันหนึ่งจะเปิดไม่ขึ้น

### ทางเลือก

| ทาง | ข้อดี | ข้อเสีย |
|---|---|---|
| ก · อ่านจากชีตตรงๆ | ไม่ต้องเปลี่ยนวิธีทำงาน | เปราะ พังเงียบ ต้องคอยซ่อม |
| ข · ย้ายเข้าระบบครั้งเดียว แล้วออก PO จากระบบ | ข้อมูลสะอาด ใช้ต่อได้ทุกเรื่อง | ต้องมีโมดูลออเดอร์ก่อน |
| **ค · ทำ import เหมือนไฟล์ราคา** | เริ่มได้เลย ไม่ต้องรอ | ต้องจัดฟอร์แมตชีตใหม่ครั้งเดียว |

**ผมแนะนำ ค** — ทำหน้าอัปโหลด PO เหมือนที่ทำกับไฟล์ราคา 751 แถว
แปลงชีตเป็นตารางแบน 1 แถว = 1 รายการ แล้วอัปครั้งเดียว ได้ลูกค้า + ออเดอร์เข้าระบบทันที
ไม่ต้องรอโมดูลออเดอร์เต็มรูปแบบ

## 7. คิดต่อให้ครบ loop (ข้อ 9)

### L1 · ต้นไม้คือ "ใบอนุญาตให้ติดต่อ" ที่ไม่มีวันหมดอายุ ★★★

ปัญหา 12-24 เดือนในเอกสารของ Bay แก้ยากมาก เพราะไม่มีเหตุผลดีๆ จะทักลูกค้า
ที่เพิ่งซื้อโซฟาไป — จะขายอะไรอีก เขาเพิ่งซื้อไป

**แต่ต้นไม้โตทุกปี**

> ปีที่ 1 · "ต้นประดู่ของครอบครัวคุณอายุครบ 1 ปีแล้ว สูง 1.2 เมตร" + รูป
> ปีที่ 2 · "ปีนี้มันออกดอกครั้งแรก"
> ปีที่ 3 · "ตอนนี้สูงเท่ากับโซฟาที่คุณซื้อแล้ว"

**นี่คือข้อความที่ลูกค้าเปิดอ่าน ไม่ใช่ข้อความขายของ** และพอถึงปีที่ 2-3
ซึ่งเป็นช่วงที่เขาเริ่มคิดจะซื้อเฟอร์นิเจอร์ชิ้นต่อไป เราอยู่ในหัวเขาแล้ว
โดยไม่เคยยัดโฆษณาให้เลยสักครั้ง

ไม่มีแบรนด์เฟอร์นิเจอร์เจ้าไหนในไทยทำแบบนี้ได้ ถ้าไม่มีระบบรองรับ

### L2 · ให้ลูกค้าตั้งชื่อต้นไม้

ต้นทุนศูนย์ ผูกใจมหาศาล · "ต้นประดู่ของบ้านสิริกาญจน์"
คนตั้งชื่อให้อะไรแล้วจะผูกพันกับมัน และจะเล่าให้คนอื่นฟัง

### L3 · ใบรับรองที่แชร์ได้ = โฆษณาฟรี

ใบรับรองรวมสองเรื่องที่คนอยากอวด — **ของดีที่ซื้อ** กับ **เรื่องดีที่ทำ**

> โซฟากีวี่ เลขที่ CC-0042
> ทำด้วยมือโดย คุณสมชาย (โครงไม้) · คุณมาลี (เย็บเบาะ) · 12 มี.ค. 2026
> ต้นประดู่ "เจ้าอ้วน" เลขที่ TR-0042 ปลูกที่ จ.น่าน 15 มิ.ย. 2026

ถ้าหน้านี้สวยและแชร์ได้ **ลูกค้าทุกคนกลายเป็นสื่อของเราหนึ่งชิ้น**
และเป็นสื่อที่น่าเชื่อถือกว่าโฆษณาที่เราซื้อเอง

### L4 · แผนที่ต้นไม้รวม — สินทรัพย์แบรนด์ที่โตเอง

หน้าสาธารณะหน้าเดียว · "ฌ เฌอ ปลูกไปแล้ว 1,247 ต้น" พร้อมแผนที่

ตัวเลขนี้โตเองทุกครั้งที่ขายได้ ไม่ต้องมีใครมาอัปเดต
เป็นคอนเทนต์ที่ใช้ได้ตลอดไปและดีขึ้นเรื่อยๆ ตามเวลา

### L5 · ชวนเพื่อนปลูก

"ปลูกเพิ่มให้เพื่อน" พร้อมโค้ดแนะนำ · เพื่อนได้ต้นไม้ในชื่อตัวเอง + ส่วนลด
ได้ลูกค้าใหม่จากคนที่เพิ่งซื้อ ในจังหวะที่เขากำลังพอใจที่สุด

### L6 · เจ้าของคนที่สอง (คิดยาว 10 ปี)

เฟอร์นิเจอร์ดีอยู่ได้หลายสิบปี ถ้าซีเรียลติดอยู่กับตัวโซฟา
วันที่มันเปลี่ยนมือ เจ้าของใหม่เปิดดูได้ว่าโซฟาตัวนี้มีที่มายังไง ใครทำ ต้นไม้อยู่ไหน

**และนั่นคือวันที่เรารู้จักลูกค้าใหม่หนึ่งคนฟรีๆ** จากของที่ขายไปเมื่อสิบปีก่อน

### L7 · ข้อมูลช่างย้อนกลับมาใช้ได้

พอผูกช่างกับตัวสินค้าแล้ว เวลามีเคลมหรือคำชม จะรู้ว่าใครทำ
ใช้ได้ทั้งแก้ปัญหาคุณภาพและให้รางวัล — ตรงกับที่ Bay เคยบอกว่าอยากมีรางวัลรายเดือน

## 8. ⚠️ เรื่องที่ต้องระวัง — ไม่พูดตอนนี้จะเจ็บทีหลัง

### R1 · ตัวเลขคาร์บอนคือกับระเบิด ★

**อย่าเคลมว่า "ต้นไม้ 1 ต้นชดเชยโซฟา 1 ตัว"**

เป็นข้อความที่ตรวจสอบได้ และเกือบแน่นอนว่าผิด
ต้นไม้ต้นหนึ่งดูดคาร์บอนราว 10-40 กก./ปี และต้องรอหลายสิบปี
ส่วนโซฟาหนึ่งตัวมี footprint จากไม้ โฟม ผ้า หนัง และการขนส่ง ซึ่งมากกว่ามาก

ไทยมี TGO (องค์การบริหารจัดการก๊าซเรือนกระจก) และทั่วโลกกำลังเอาจริงกับ greenwashing

> **แนะนำ: เปลี่ยนจาก "ชดเชย" เป็น "เราปลูกให้"**
> *"ซื้อโซฟา 1 ตัว เราปลูกต้นไม้ 1 ต้น"* — จริง ตรวจสอบได้ ไม่ต้องเคลมตัวเลข
>
> ถ้าจะโชว์ตัวเลขคาร์บอน ให้อ้างอิงแหล่งที่มาและใช้เป็นช่วง 10-20 ปี
> ห้ามใช้คำว่า carbon neutral / ชดเชยหมด / net zero เด็ดขาด

### R2 · ถ้าไม่ได้ปลูกจริง แย่กว่าไม่ทำเลย

ต้องมีพาร์ทเนอร์จริง มีพิกัด มีรูป มีคนรับผิดชอบ
ลูกค้าสมัยนี้ไม่เชื่อคำว่า "เราปลูกให้แล้ว" ถ้าไม่มีหลักฐาน

### R3 · ต้นไม้ปลูกตามฤดู ไม่ใช่ปลูกทันที

ลูกค้ากดเลือกเดือนมีนาคม แต่ปลูกจริงเดือนมิถุนายน
หน้าเว็บต้องบอกให้ชัดตั้งแต่แรกว่า *"จะปลูกในรอบเดือน ___ แล้วส่งรูปให้"*
ไม่ใช่ปล่อยให้เขาคิดว่าปลูกวันนี้

### R4 · ค่าใช้จ่ายต่อต้นต้องรู้ก่อนเริ่ม

ค่ากล้า + ค่าปลูก + ค่าดูแล 3 ปี + ค่าถ่ายรูปรายปี
ถ้าไม่คิดค่าดูแลกับค่าถ่ายรูป พอขายได้เดือนละ 50 ตัว L1 จะกลายเป็นภาระ

## 9. ทางที่เริ่มได้เร็วที่สุด (ถ้า Bay อยากลอง)

ไม่ต้องรอโมดูลออเดอร์เต็มรูปแบบ

1. จัดชีต PO ใหม่เป็นตารางแบน (1 แถว = 1 รายการ) ครั้งเดียว
2. อัปโหลดเข้าระบบเหมือนไฟล์ราคา → ได้ลูกค้า + ออเดอร์ย้อนหลังราว 60 ใบ
3. ทำหน้าลูกค้าหน้าเดียว (ซื้ออะไร + เลือกต้นไม้ + ใบรับรอง)
4. ส่งลิงก์ให้ลูกค้าเก่าทาง Line → **ทดสอบว่ามีคนกรอกจริงกี่ %**
5. ถ้าได้ผล ค่อยต่อ offline conversion, แผนที่, อีเมลรายปี

**ข้อ 4 คือจุดตัดสิน** ถ้าลูกค้าเก่าไม่กรอก แปลว่า hook ยังไม่แรงพอ
รู้ตั้งแต่ตอนนี้ดีกว่ารู้ตอนสร้างทั้งระบบเสร็จ
