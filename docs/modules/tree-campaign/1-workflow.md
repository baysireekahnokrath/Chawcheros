## ง. ทีละขั้น

### W1 · ออก PO → ระบบนับต้นไม้ + ออกลิงก์ — *ระบบ*

| | |
|---|---|
| เริ่มเมื่อ | ฝ่ายขายออก PO (เลข BLS) |
| ระบบทำ | นับว่าออเดอร์นี้ได้กี่ต้นตามกฎ A3-A5 · ออก **เลขต้นไม้ TR-xxxx จองไว้** ตามจำนวน · ออก **ลิงก์ส่วนตัว** ที่เดาไม่ได้ (B1) |
| คนทำ | ฝ่ายขาย **เห็นจำนวนต้นก่อนบันทึก** · ถ้าโมดูลาร์ต่อเป็นคนละตัว กดปรับได้ (A4) |
| ส่งต่อ | → W2 |

### W2 · ส่งลิงก์ให้ลูกค้า — *ฝ่ายขาย*

| | |
|---|---|
| เมื่อไหร่ | **ทันทีหลังออก PO** ไม่ต้องรอส่งของ (ดู C2) |
| ทางไหน | ❓ Line / SMS / อีเมล (B1-Q4 · ดู N3) |
| ลูกค้าเห็น | ซื้ออะไร ราคาเท่าไหร่ · สถานะตอนนี้ · ช่องเลือกต้นไม้ |
| ส่งต่อ | → W3 (ลูกค้า) และ W6 (โรงงาน) เดินคู่กันไป ไม่รอกัน |

### W3 · ลูกค้าเลือกต้นไม้ — *ลูกค้า*

ลูกค้าทำในหน้าเดียว ไม่ต้องสมัคร

1. ดูว่าซื้ออะไรไป (ไม่มีต้นทุน ไม่มีกำไร ไม่มีข้อมูลคนอื่น)
2. เลือก **พันธุ์** (❓ Q4) และ **ที่ปลูก** บางกระเจ้า / เขาใหญ่ (❓ Q9) — ทีละต้น ถ้าได้หลายต้น
3. **ตั้งชื่อต้นไม้** (ไม่บังคับ)
4. ใส่/ยืนยัน **เบอร์หรืออีเมล** ที่จะรับข่าวต้นไม้
5. ติ๊ก **ความยินยอม** — 2 ช่องแยกกัน (ดู C4)
6. กด **"ปลูกให้ผม"**

| ถ้า... | แล้ว... |
|---|---|
| ลูกค้าไม่เปิดลิงก์ / ไม่กด | **ยังปลูกให้อยู่ดี** ด้วยพันธุ์ตั้งต้น หลัง ❓ N4 วัน (ดู C3) · ชื่อมาตั้งทีหลังได้ |
| อยากแก้พันธุ์หลังกดแล้ว | แก้ได้จนกว่าจะเพาะ (W4) · เพาะแล้วแก้ได้แค่ชื่อ |

ส่งต่อ → W4 (แปลงเพาะเห็นในรายการ "ต้องเพาะ") และ W5

### W4 · เพาะกล้า + ติดป้าย — *คนดูแลแปลงเพาะ*

| | |
|---|---|
| เห็นอะไร | รายการต้นที่ต้องเพาะ: เลข TR · พันธุ์ · ชื่อที่ลูกค้าตั้ง |
| ทำ | เพาะ · ติดป้ายเลข TR (และชื่อ) · **ถ่ายรูป 1 รูป** · กดบันทึก |
| ระยะ | ❓ ภายในกี่วันหลังลูกค้ากด (ผมเสนอ 7 วัน ตาม 0-idea) |
| ลูกค้าเห็น | ส่วน "ต้นไม้ของคุณ" เปลี่ยนเป็น **"เพาะแล้ว"** + รูปกล้าของตัวเอง |
| แจ้งลูกค้า | ครั้งที่ 1 · ❓ ใครส่ง ส่งทางไหน (ดู C8) |
| ส่งต่อ | → รอโต แล้วไป W8 |

### W5 · ส่งสัญญาณให้ Meta / Google — *ระบบ*

เกิดตอนลูกค้ากด "ปลูกให้ผม" — **สองเรื่องที่ต่างกัน** (ตาม 0-idea ข้อ 3)

| | Pixel + Google tag บนหน้า | Offline conversion |
|---|---|---|
| ส่งอะไร | "มีคนกรอกหน้านี้" | **มูลค่าที่ซื้อจริง + วันที่ซื้อ + เบอร์/อีเมลที่เข้ารหัส** |
| ใช้ทำอะไร | สร้าง audience ยิงซ้ำ · นับว่ามีคนกรอกกี่คน | ให้ Meta/Google รู้ว่า **โฆษณาตัวไหนทำให้ขายได้จริง** |
| เงื่อนไข | ตามนโยบายคุกกี้ของเว็บ | **ต้องติ๊กยินยอมช่องที่ 2 เท่านั้น** ไม่ติ๊ก = ไม่ส่ง |
| ต้องมี | ❓ Q8 บัญชี Meta Business + Google Ads |

⚠️ แพลตฟอร์มรับ offline conversion **ย้อนหลังได้จำกัด** (ราวๆ 2-3 เดือนหลังวันซื้อ — ต้องตรวจตัวเลขจริงตอนด่าน 4)
แปลว่า **ยิ่งส่งลิงก์เร็ว ยิ่งได้ข้อมูลโฆษณา** (เหตุผลหลักของ C2) และ PO เก่าอาจเลยกรอบไปแล้ว (ผลต่อ Q7)

### W6 · ผลิต + บันทึกช่าง + ป้าย serial — *ช่าง / โรงงาน*

| | |
|---|---|
| ทำ | ผลิตตามปกติ · ยิงป้าย serial CC-xxxx · **ไม่ต้องบันทึกช่างระหว่างผลิต** |
| บันทึกช่าง | ✅ **key ตามหลัง** (Bay ตอบ N2) — บันทึกย้อนหลังว่าใครทำส่วนไหน วันไหน ลงช่อง `made_by` `made_on` `made_at` ที่มีอยู่แล้ว |
| ผูก | ระบบผูก **ตัวโซฟา ↔ ต้นไม้** อัตโนมัติ (โซฟาตัวที่ 1 ของออเดอร์ = TR ตัวที่ 1) |
| ลูกค้าเห็น | ส่วน "ตอนนี้ของอยู่ไหน" → กำลังผลิต (❓ ละเอียดแค่ไหน · B1-Q5) |
| ผลที่ตามมา | ① **ป้ายเลเซอร์มีแค่เลข serial** ไม่มีชื่อช่าง (ยิงก่อนรู้ชื่อ) · ชื่อช่างไปอยู่บนใบรับรองออนไลน์ที่เปิดจากเลขนั้น<br>② ใบรับรองขึ้นชื่อช่าง **เมื่อ key แล้ว** ระหว่างนั้นขึ้นว่า *"ผลิตที่โรงงาน ฌ เฌอ"* (แบบเดียวกับ C9)<br>③ ระบบทำรายการ **"ตัวที่ยังไม่มีชื่อช่าง"** ไว้ตาม ไม่งั้นจะลืม key แล้วใบรับรองว่างตลอดไป |
| ของจากสต็อก | ของที่ผลิตไว้แล้ว (B22) อาจไม่รู้ว่าใครทำ → แสดงเท่าที่รู้ (ดู C9) |

### W7 · จัดส่ง → ใบรับรองครบ — *จัดส่ง*

| | |
|---|---|
| ทำ | อัปเดตสถานะการส่ง · ใส่เลข tracking ถ้าใช้ขนส่งภายนอก (❓ B1-Q1) |
| ลูกค้าเห็น | ส่งแล้ว → ถึงแล้ว · ส่งหลายรอบก็เห็นทีละรอบ (A9) |
| พอส่งครบ | ส่วน "ใบรับรอง" **ครบ** — โซฟาเลขที่ / ทำโดย / ต้นไม้เลขที่ / ปลูกที่ · มีปุ่ม **แชร์** (ดู C1) |

### W8 · ย้ายลงดิน — *คนดูแลแปลงเพาะ*

| | |
|---|---|
| เมื่อไหร่ | เป็น **รอบ** ไม่ใช่รายต้น · ❓ ปีละกี่รอบ เดือนไหน (Q2) |
| เห็นอะไร | รายการกล้าที่ "พร้อมย้าย" ของแต่ละแปลง |
| ทำ | ขนไปทั้งล็อต · ปลูก · **ถ่ายรูป + พิกัด GPS ทีละต้น** · กดบันทึก |
| ลูกค้าเห็น | "ปลูกลงดินแล้วที่ ___" + รูป + ปุ่มเปิดแผนที่ · "มาเยี่ยมได้" |
| แจ้งลูกค้า | ครั้งที่ 2 |
| จบ | **งานรายต้นของคนในบริษัทจบตรงนี้** |

### W9 · ทุกปี — *คนดูแลแปลง + ฝ่ายขาย/การตลาด*

| | |
|---|---|
| ทำ | ถ่าย **รูปรวมทั้งแปลง** (โดรน) แปลงละ 1 ชุด · อัปเดตตัวเลขรวม "ปลูกไปแล้ว ___ ต้น" |
| ลูกค้าเห็น | รูปแปลงของต้นตัวเอง + อายุต้นไม้ "ครบ 1 ปีแล้ว" |
| แจ้งลูกค้า | ปีละครั้ง เฉพาะคนที่ยินยอมช่องที่ 1 |
| ❓ | รับข้อเสนอรูปรวมไหม (Q3) |

### W10 · ลูกค้ามาเยี่ยม — *ลูกค้า*

ลูกค้าเปิดพิกัดจากลิงก์แล้วไปเอง · ❓ ต้องนัดก่อนไหม มีคนต้อนรับไหม (ดู N5)

## ฉ. เรื่องที่ผมตัดสินใจเอง — ตรงนี้แหละที่อยากให้พี่ตรวจ

### C1 · ลิงก์เดียวกับ B1 แต่มี **2 หน้า** — ส่วนตัว กับ แชร์ได้

B1 บอกว่าลิงก์ **ควรหมดอายุ** หลังส่งของ แต่ต้นไม้ต้องอยู่ **ตลอดไป** — ขัดกันตรงๆ
และถ้าลูกค้ากดแชร์ลิงก์ส่วนตัว คนทั้งโลกจะเห็นที่อยู่ เบอร์ ราคาที่เขาจ่าย

| | ลิงก์ส่วนตัว | ใบรับรองสาธารณะ |
|---|---|---|
| ใครได้ | ลูกค้าคนเดียว (เราส่งให้) | ใครก็ได้ที่ลูกค้าแชร์ให้ |
| เห็นอะไร | ทุกอย่างในตาราง จ. | **ชื่อสินค้า · serial · ชื่อช่าง · ต้นไม้ · ชื่อต้นไม้ · ที่ปลูก** เท่านั้น |
| ไม่เห็น | — | ราคา · ที่อยู่ · เบอร์ · สถานะส่ง |
| หมดอายุ | ส่วน "ของอยู่ไหน" ซ่อนหลังส่งครบ ❓ กี่วัน · ส่วนอื่นอยู่ตลอด | ไม่หมดอายุ |

ปุ่ม "แชร์" ในลิงก์ส่วนตัว **แชร์ใบรับรองสาธารณะเสมอ** ไม่เคยแชร์ลิงก์ส่วนตัว

### C2 · ส่งลิงก์ทันทีหลังออก PO ไม่รอส่งของ

- ลูกค้าตื่นเต้นที่สุดตอนเพิ่งจ่ายมัดจำ
- กรอบเวลา offline conversion (W5) นับจากวันซื้อ — รอ 45 วันจนส่งของ อาจเสียไปครึ่งกรอบ
- ระหว่างรอผลิต ลูกค้ามีอะไรให้ดู (กล้าของตัวเองโต) แทนที่จะทักมาถามว่า "ของถึงไหนแล้ว"

### C3 · ลูกค้าไม่กด ก็ยังปลูกให้

เราพูดว่า *"ซื้อโซฟา 1 ตัว เราปลูกต้นไม้ 1 ต้น"* — ถ้าไม่ปลูกเพราะลูกค้าไม่กรอก คำพูดนี้ไม่จริง (R2)
→ ครบ N4 วันแล้วยังไม่เลือก ระบบใส่พันธุ์ตั้งต้นให้ แปลงเพาะเห็นเป็นงานปกติ

### C4 · ความยินยอม 2 ช่อง แยกกัน · ไม่ติ๊กก็ได้ต้นไม้

| ช่อง | เขียนว่า (ร่าง) | ไม่ติ๊กแล้วเป็นไง |
|---|---|---|
| 1 | ส่งข่าวต้นไม้ของฉันทาง ___ ปีละครั้ง | ยังได้ต้นไม้ · ดูในลิงก์ได้ · แค่เราไม่ทักไป |
| 2 | ให้ ฌ เฌอ ส่งข้อมูลการซื้อแบบเข้ารหัสไปให้ Meta/Google เพื่อวัดผลโฆษณา | ยังได้ต้นไม้ · แค่ไม่ส่ง offline conversion |

**ห้ามผูก "ได้ต้นไม้" กับ "ต้องยินยอม"** — PDPA ไม่ให้บังคับแลก และถ้าบังคับ คนจะไม่ไว้ใจทั้งหน้า
ข้อความจริงต้องให้ฝ่ายกฎหมาย/ที่ปรึกษาอ่านก่อนขึ้นด่าน 4

### C5 · เลข TR ออกตั้งแต่ W1 ไม่ใช่ตอนเพาะ

ลูกค้าเห็นเลขต้นไม้ตัวเองตั้งแต่วันแรก ใบรับรองร่างมีเลขครบ · ป้ายจริงพิมพ์ตอน W4

### C6 · ยกเลิกออเดอร์ → ต้นไม้ไม่ถูกลบ

| ยกเลิกตอนไหน | ต้นไม้ |
|---|---|
| ก่อนเพาะ | เลข TR เปลี่ยนสถานะ "ยกเลิก" (A10 ห้ามลบ) |
| เพาะแล้ว | กลายเป็น **"ต้นของ ฌ เฌอ"** ปลูกต่อตามปกติ นับในตัวเลขรวม · ❓ หรือเอาไปให้ออเดอร์ถัดไป |

### C7 · ต้นตาย → ปลูกซ่อม และบอกลูกค้าตรงๆ

กล้าตายเป็นเรื่องปกติ ระบบบันทึกว่าตาย → ปลูกต้นใหม่ **เลข TR เดิม** · หน้าลูกค้าขึ้นว่า *"ปลูกซ่อมเมื่อ ___"*
ไม่ซ่อน เพราะถ้าลูกค้ามาเยี่ยมแล้วเจอว่าไม่ตรง จะเสียความเชื่อใจทั้งแคมเปญ (R2) · ❓ พี่โอเคไหม

### C8 · "แจ้งลูกค้า" ระยะแรก = คนส่งเอง ไม่ใช่ระบบ

B1.4 บอกไม่ต้องมีระบบแจ้งเตือน → ระยะแรก **ข้อมูลบนหน้าอัปเดตเอง** ส่วนการทักลูกค้า ระบบแค่ทำ **รายการ "ใครควรได้ข่าวรอบนี้"** ให้ฝ่ายขายส่งเองทาง Line
ส่งอัตโนมัติค่อยทำทีหลัง ถ้าจำนวนเยอะจนส่งเองไม่ไหว

### C9 · ข้อมูลช่างที่ไม่รู้ → ไม่เดา

ของจากสต็อกเก่า (ก่อนเริ่มบันทึก) ใบรับรองแสดงแค่ *"ผลิตที่โรงงาน ฌ เฌอ"* ไม่ใส่ชื่อช่างที่ไม่แน่ใจ

### C10 · คำที่ใช้ — "เราปลูกให้" ไม่ใช่ "ชดเชย"

ตาม R1 ใน 0-idea · ตัวเลขคาร์บอน **ไม่แสดงในเฟสแรก** ถ้าจะแสดงทีหลังต้องมีแหล่งอ้างอิงและเป็นช่วง 10-20 ปี
ห้ามคำว่า carbon neutral / ชดเชย / net zero

### C11 · ข้อมูลออเดอร์ระยะแรกมาจาก **import PO** (ทาง ค)

โมดูลออเดอร์ยังไม่มี · W1 ระยะแรกจึงเกิดตอน **อัปโหลดชีต PO แบบแบน** ไม่ใช่ตอนออก PO ในระบบ
พอโมดูลออเดอร์มา W1 ย้ายไปเกิดตอนออก PO เอง **workflow ที่เหลือไม่เปลี่ยน**
❓ พี่ยังไม่ได้ยืนยันทาง ค (ดู N6)
