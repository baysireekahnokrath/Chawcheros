## 1 · หลักที่ใช้ตัดสินโครงสร้าง

### 1.1 แยก "สูตร" ออกจาก "ราคา" เพราะคนละคนเห็น

| | ใครต้องเห็น |
|---|---|
| **สูตรวัสดุ** — ใช้หนังกี่ฟุต ขากี่ขา ฟองน้ำเกรดไหน | คุณหนิง (จัดซื้อ) · โรงงาน · ไม่เห็นก็สั่งของไม่ได้ |
| **ราคาต่อหน่วย · กำไร · ราคาโอน** | 🔒 **เจ้าของเท่านั้น** |

→ สูตรอยู่ schema `production` (พนักงานอ่านได้) · ราคาอยู่ schema `cost` (ต้องมี `cost.read`)

**ต้นทุน = สูตร × ราคา** จึงตกอยู่ใน `cost` โดยอัตโนมัติ ไม่ต้องกั้นเพิ่ม

### 1.2 1 สูตร ครอบทุกเกรด — ไม่ใช่ 751 สูตร

ใบ costing ที่โรงงานใช้อยู่เป็น **1 ใบ หลายคอลัมน์เกรด** และเปลี่ยนแค่ราคาวัสดุหุ้ม
ระบบทำแบบเดียวกัน — สูตรผูกกับ **รุ่น + ขนาด** ส่วนวัสดุหุ้มเป็น "ช่องว่าง" ที่เติมตามเกรดของตัวสินค้านั้น

> 751 ตัวสินค้า → เหลือสูตรราว **150 ใบ** · งานกรอกลดลง 5 เท่า
> และเข้ากับกฎที่ตกลงไว้ว่าเกรดวัสดุเป็นคุณสมบัติของตัวสินค้า ไม่ใช่ตัวเลือกตอนขาย

### 1.3 ไม่เก็บตัวเลขที่คำนวณได้ (กฎ A10)

ปริมาณรวมหลังหักของเสีย · มูลค่าต่อบรรทัด · ต้นทุนรวม · ราคาตามนโยบาย · กำไร % · พื้นส่วนลด
— **คำนวณสดทุกครั้ง** · ราคาวัสดุขยับเมื่อไหร่ ต้นทุนทุกรุ่นขยับเอง ไม่มีใครต้องไล่แก้

### 1.4 บอกตรงๆ ว่าตัวไหนยังเดาอยู่

Bay ยืนยันเองว่า**ค่าแรงวันนี้ประเมินจากความรู้สึก** → ทุกราคามีช่อง `เป็นค่าประเมิน`

ใบเสนอราคาจึงบอกได้ว่า *"ต้นทุนใบนี้มีส่วนที่ยังเดาอยู่กี่ %"* — ไม่ใช่แสร้งว่าแม่นทั้งหมด

## 3 · ⚠️ สองกับดักจากใบเดิม ที่ต้องแก้ตั้งแต่วันแรก

### 3.1 คำว่า `MARK UP` ในใบเดิม ที่จริงคือ **กำไรขั้นต้น**

```
สูตรที่ใบใช้จริง   ราคา = ต้นทุน ÷ (1 − อัตรา)      ← กำไรขั้นต้น
ถ้าอ่านตามชื่อ     ราคา = ต้นทุน × (1 + อัตรา)      ← markup · ราคาจะต่ำกว่าเดิม
```

สูตรในใบถูก **แต่ชื่อผิด** · วันไหนมีคนแก้ให้ตรงกับชื่อ ราคาจะตกทั้งกระดาน

→ ในระบบใช้ชื่อ **`gross_margin_pct`** และหน้าจอเขียน **"กำไรขั้นต้น"** · ไม่มีคำว่า markup ที่ไหนเลย

### 3.2 ค่าแรง + ขนส่ง + บรรจุ ถูกยุบเป็นก้อนเดียวที่เดาเอา

→ ในระบบ **แยกเป็น 3 บรรทัดจริง** แต่ละบรรทัดติดธง `is_estimate`
→ พอวันหนึ่งวัดค่าแรงจริงได้ เปลี่ยนเฉพาะบรรทัดนั้น ไม่ต้องรื้อสูตร

## 4 · สูตรคำนวณ · ทุกตัวเป็นวิว ไม่มีช่องให้ใครพิมพ์

```
ต่อบรรทัดในสูตร
    ปริมาณที่ต้องซื้อ = net_qty ÷ recovery
    มูลค่า          = ปริมาณที่ต้องซื้อ × pieces × ราคาต่อหน่วย ณ วันที่คิด

ต่อตัวสินค้า
    ต้นทุนรวม        = Σ มูลค่าทุกบรรทัด   ← วัสดุหุ้มใช้ราคาตามเกรดของตัวนั้น
    ราคาตามนโยบาย    = ต้นทุนรวม ÷ (1 − gross_margin_pct)
    ส่วนที่เผื่อไว้    = transfer_price − ราคาตามนโยบาย
    กำไรจริง         = (ราคาขายจริง − ต้นทุนรวม) ÷ ราคาขายจริง
    พื้นส่วนลด        = ต้นทุนรวม          ★ ต่ำกว่านี้คือขาดทุนจริง
    % ที่ยังเดา       = Σ มูลค่าที่ is_estimate ÷ ต้นทุนรวม
```

| วิว | ตอบอะไร |
|---|---|
| `cost.v_bom_cost` | ต้นทุนรายบรรทัด หน้าตาเหมือนใบ costing เดิม — ตรวจย้อนได้ถึงวัสดุ |
| `cost.v_variant_cost` | ต้นทุนรวม · ราคาตามนโยบาย · ราคาโอน · **ส่วนที่เผื่อไว้** · % ที่ยังเดา |
| `cost.v_margin_check` | ราคาขายจริงทั้งแคตตาล็อก vs ต้นทุนจริง — **รุ่นไหนกำไรต่ำกว่าที่ตั้งไว้** |
| `cost.v_quote_costing` | ใบเสนอราคา 1 ใบ พร้อมต้นทุนทุกบรรทัด |

ตัวเลขข้างล่างเป็น **โครงหน้าจอ ไม่ใช่ข้อมูลจริง**

   🔒 ต้นทุน — · กำไร —% · ลดได้ถึง —
      ⚠ ต้นทุนนี้มีส่วนที่ยังเป็นค่าประเมิน —%
      ├ ไส้        net — ÷ rec — = — × ราคา — = —
      ├ ผ้าซับใน   net — ÷ rec — = — × ราคา — = —
      ├ วัสดุหุ้ม   net — ÷ rec — = — × — ชิ้น  = —

## 6 · ข้อมูลเข้าระบบยังไง · นี่คือคอขวดจริง

ใบ costing หลายร้อยใบ กรอกมือไม่ไหว → ใช้วิธีเดียวกับไฟล์ราคาที่ทำไปแล้ว คือกรอกในชีตแล้วนำเข้า

### ชีตที่ 1 · ราคาวัสดุ — คุณหนิงกรอก (ตอบ PRQ21)

| รหัส | ชื่อวัสดุ | หน่วย | ราคา/หน่วย | ได้เนื้อ | ราคานี้มาจาก | วันที่ | เป็นค่าประเมิน |
|---|---|---|---|---|---|---|---|
| | | ตร.ฟุต · เมตร · นิ้ว · ขา · กก. | | | PO · ใบเสนอราคา · ประเมิน | | ✓/ว่าง |

**กรอกครั้งเดียว ใช้กับทุกรุ่น** — ซัพพลายเออร์ขึ้นราคา แก้บรรทัดเดียว ต้นทุนทุกรุ่นขยับเอง
**นี่คือชีตที่ Bay ขอให้เตรียมไว้ให้คุณหนิง**

### ชีตที่ 2 · สูตร — ถอดจากใบ costing เดิม

| รุ่น | ขนาด | ลำดับ | รหัสวัสดุ | NET | ได้เนื้อ | กี่ชิ้น | หมายเหตุ |
|---|---|---|---|---|---|---|---|
| | | | *(เว้นว่าง = ช่องวัสดุหุ้ม)* | | | | |

**คอลัมน์ตรงกับใบ costing เดิมทุกช่อง** — คนที่ทำใบ costing อยู่แล้วกรอกได้เลย ไม่ต้องเรียนใหม่

## 9 · สิ่งที่เจอตอนสร้างจริง · สามเรื่องที่โครงบนกระดาษไม่ได้บอก

### 9.1 🔴 ช่องโหว่สิทธิ์ที่ RLS ปิดไม่ได้ — เจอด้วยการทดสอบข้อ 6

RLS ปิด **ตาราง** `cost.component_prices` ได้ แต่ไม่ได้ปิด **วิว** ที่อ่านตารางนั้น

คนที่ไม่มี `cost.read` จึงเห็นแถวของ `cost.v_variant_cost` ได้ — ไม่ใช่เห็นราคา
แต่เห็น "ต้นทุน = 0" เพราะ `sum()` ของค่าว่างได้ศูนย์

> ศูนย์แย่กว่าว่าง · ว่างแปลว่าไม่รู้ ศูนย์แปลว่าฟรี
> ฝ่ายขายที่เห็นพื้นส่วนลด 0 จะลดได้ไม่จำกัดโดยเชื่อว่าตัวเลขรับรองแล้ว

→ ทุกวิวใน `cost` ที่อ่านข้ามเข้ามาจาก `production` ต้องมี `where core.has_capability('cost.read')`
ของตัวเอง · ไม่พึ่ง RLS ของตารางข้างล่างเพียงอย่างเดียว

### 9.2 ต้นทุนมีสองชั้น และพื้นส่วนลดต้องใช้ชั้นที่จ่ายเงินจริง

|  | คืออะไร | ใช้ทำอะไร |
|---|---|---|
| **ต้นทุนผลิต** | Σ สูตร × ราคาวัสดุ | รู้ว่าของจริงแพงเท่าไหร่ · ใช้คิดราคาตามนโยบาย |
| **ต้นทุนที่เราจ่าย** | ราคาโอนจากบริษัทแม่ | ★ พื้นส่วนลด · เงินที่ออกจากบัญชีจริง |

ถ้าใช้ต้นทุนผลิตเป็นพื้นส่วนลด ระบบจะอนุญาตให้ลดลงไปถึงจุดที่
**ตัวเลขบอกว่ายังกำไร แต่เงินจริงขาดทุน** เท่ากับส่วนต่างของสองชั้นคูณจำนวน

→ `cost.v_variant_cost` ตอบทั้งสองชั้น และคอลัมน์ `พื้นส่วนลดรวม_vat`
ใช้ `coalesce(ราคาโอน, ต้นทุนผลิต) × (1 + VAT)` เสมอ

### 9.3 สูตรที่ราคายังไม่ครบ ต้องตอบว่า "ยังตอบไม่ได้"

`sum()` ของบรรทัดที่ไม่มีราคา ให้ตัวเลขที่ **ต่ำกว่าจริงโดยไม่มีใครรู้**

→ `ต้นทุนผลิต` เป็นค่าว่างทันทีที่มีบรรทัดไหนยังไม่มีราคา
→ `ต้นทุนที่คิดได้แล้ว` บอกเท่าที่คิดได้ · `บรรทัดที่ยังไม่ครบ` บอกว่าขาดกี่บรรทัด
→ `ราคาตามนโยบาย` และ `พื้นส่วนลด` เป็นค่าว่างตามไปด้วย — ไม่เดาให้

## 10 · ของแถมที่ปิดเรื่องนราธิวาสไปด้วย

ใบเสนอราคามีช่อง `shipping_terms` ที่ค่าตั้งต้นคือ **"ยังไม่ได้คุย"**
และ `sales.send_quote()` **ปฏิเสธการส่ง** ตราบใดที่ยังเป็นค่านั้น

| ตัวเลือก | ความหมาย |
|---|---|
| ยังไม่ได้คุย | ★ ส่งใบเสนอราคาไม่ได้ |
| ส่งฟรี | |
| คิดค่าส่งตามที่ระบุ | ต้องใส่จำนวนเงิน ไม่งั้นไม่ผ่าน |
| ลูกค้าจ่ายตามจริง | |
| ลูกค้ามารับเอง | |

> เรื่องนราธิวาส 17,000 บาท ไม่ได้เริ่มจากคนลืม · เริ่มจากฟอร์มที่ไม่มีช่องให้ลืม
> บังคับที่ฐานข้อมูล ไม่ใช่ที่หน้าจอ จึงเลี่ยงด้วยการกรอกผ่านทางอื่นไม่ได้

ช่อง `shipping_note` เก็บว่าตกลงกับใครไว้อย่างไร — ตอบคำถาม
*"sales ก็จำไม่ได้ ว่าคุยกับลูกค้าไว้อย่างไร"* ได้ตรงๆ

| CQ4 ใบเสนอราคามีอายุกี่วัน | **ตั้งต้น 30 วัน** | ใส่ตัวเลขอื่นได้ทุกครั้งที่ออกใบ |

| CQ6 งานสั่งทำที่ยังไม่มี SKU | **ทำได้แล้ว** | `quote_lines.variant_id` ว่างได้ · ใส่ชื่อรายการกับราคาเอง |
| **CQ7** | **ตอบแล้ว 2026-11-07** | ★ ราคาโอนจากบริษัทแม่เป็นราคา **ก่อน VAT** — Bay ยืนยัน · ตรงกับที่ระบบคิดไว้ ไม่ต้องแก้สูตร |

> **CQ7 สำคัญกว่าที่เห็น** · ถ้าราคาโอนเป็นราคารวม VAT แล้ว แต่ระบบคิดว่าก่อน VAT
> พื้นส่วนลดจะสูงเกินจริง 7% ทุกตัว และกำไรที่รายงานจะต่ำกว่าจริง — เพี้ยนทั้งแคตตาล็อก
> ตอนนี้ยืนยันแล้วว่าก่อน VAT · สูตรที่ใช้จึงถูก:
>
> ```
> พื้นส่วนลดรวม VAT = ราคาโอน × (1 + VAT)
> กำไรจริง         = ราคาขายก่อน VAT − ราคาโอน      ← ทั้งสองข้างก่อน VAT เหมือนกัน
> ```

## 12 · บทเรียนที่ไม่เกี่ยวกับต้นทุนเลย

ชื่อคอลัมน์ภาษาไทยใน Postgres ยาวได้ไม่เกิน **63 ไบต์** = ประมาณ **21 ตัวอักษร**
เกินนั้นถูกตัดทิ้งโดยแจ้งเป็น `NOTICE` ไม่ใช่ `ERROR` — migration ยังผ่าน

เจอว่า 0033 มีคอลัมน์หนึ่งถูกตัดไปตั้งแต่ตอนนั้น และโค้ดหน้าเว็บอ่านชื่อเต็ม
จึงได้ `undefined` ทุกครั้ง · **หน้ารายการออเดอร์นับ "เลยกำหนด" ได้ 0 เสมอ**
ไม่มี error ให้เห็น ตัวเลขแค่บอกว่าไม่มีปัญหา — 0038 แก้แล้ว

→ กฎใหม่: ตั้งชื่อคอลัมน์ไทยไม่เกิน 20 ตัวอักษร และดู `NOTICE` ทุกครั้งที่รัน migration
