## ★ ทำไมหน้าแยกถึงช่วยเรื่อง tag ได้จริง

ตอนนี้ปุ่มกระจายอยู่หลายหน้า คนกดแล้วออกไป LINE ทันที → event ยิงไม่ทันบ้าง ยิงบางหน้าบ้าง

| ถ้ามีหน้า `/showroom/` | ได้อะไร |
|---|---|
| ปุ่ม "นัดวันเข้าชม" ทุกที่ชี้มาหน้านี้ก่อน | นับที่**จุดเดียว** · แก้ปัญหานับไม่ครบไปในตัว |
| คนเข้าหน้านี้ | Meta + Google เก็บเป็น **audience "สนใจโชว์รูม"** ยิงโฆษณาซ้ำได้ แม้ไม่กดปุ่ม |
| คนกดปุ่ม LINE บนหน้านี้ | ยิง conversion ครบ 3 ที่ในครั้งเดียว (ตารางล่าง) |
| ลิงก์จากโพสต์ FB/IG ติด UTM มาที่หน้านี้ | รู้ว่าโพสต์ไหนพาคนมานัดจริง (ต่อกับ S-03 ของโมดูลคอนเทนต์) |

### event ที่ยิงตอนกดปุ่ม

| ที่ | event | หมายเหตุ |
|---|---|---|
| GA4 | `book_showroom` | ชื่อเดียวกับที่ตกลงไว้ใน P6 โมดูลคอนเทนต์ · ตั้งเป็น key event |
| Google Ads | conversion ของ `AW-11359947999` | ต้องสร้าง conversion action ใน Google Ads ก่อน แล้วเอา label มา |
| Meta Pixel | `Schedule` (standard event ของ Meta สำหรับ "นัดหมาย") | ถ้ายังไม่มี Pixel ต้องติดก่อน |

**จุดที่พังง่าย:** กดแล้วเปิด LINE ทันที browser ตัดก่อนส่ง event
→ ยิงด้วย `transport: beacon` และหน่วงเปิด LINE ~300ms (คนไม่รู้สึก)

### ⚠️ ข้อจำกัดที่ต้องรู้

- **กดปุ่ม ≠ นัดจริง** · เรารู้แค่ว่าคนกดไป LINE · นัดได้จริงไหมรู้ใน LINE chat
  ทีหลังถ้าบันทึกการนัด/การมาจริงในระบบเรา (CRM) ส่งกลับเป็น offline conversion ให้ Meta/Google ได้ = โฆษณาฉลาดขึ้นมาก (เฟสถัดไป)
- **PDPA** · Pixel + remarketing ควรมีแถบขอความยินยอมคุกกี้ · ต้องเช็กว่าเว็บมีแล้วหรือยัง

## ★ เพิ่ม 2026-11-04 · นับ "คนที่มาโชว์รูมจริง จากโฆษณา"

> อยาก count คนที่มา showroom จาก ad

### ปัญหา: สายโซ่ขาด 2 จุด

```
เห็นโฆษณา → กดเข้าเว็บ → กดปุ่ม LINE ─✂─ คุยในแชท ─✂─ มาโชว์รูมจริง
  ↑ Meta/Google รู้               รู้ถึงตรงนี้      ไม่มีใครรู้ว่าคนที่มาคือคนจากโฆษณาไหน
```

ต้องมี "ตัวต่อ" ข้ามรอยขาดทั้งสองจุด

### วิธีที่แนะนำ · รหัสนัด + เช็กอินหน้าโชว์รูม

| # | ขั้น | ทำยังไง |
|---|---|---|
| 1 | คนกดปุ่มบนหน้า `/showroom/` | หน้าเว็บสร้าง**รหัสนัด** เช่น `CC-4821` · เก็บคู่กับ `gclid` / `fbclid` / UTM (มาจากโฆษณาไหน) ลงระบบเรา |
| 2 | เปิด LINE พร้อมข้อความพิมพ์ไว้ให้แล้ว | *"สวัสดีครับ อยากนัดชมโชว์รูม (รหัส CC-4821)"* · ลูกค้ากดส่งอย่างเดียว · ใช้ลิงก์ `line.me/R/oaMessage/@<OA ID>/?ข้อความ` แทน `lin.ee` (lin.ee ใส่ข้อความล่วงหน้าไม่ได้) |
| 3 | แอดมินนัดในแชทตามปกติ | เห็นรหัสในแชท · บันทึกนัดในระบบเรา (หรือ bot อ่านรหัสให้เอง ถ้า OA นี้ต่อ webhook แล้ว) |
| 4 | **ลูกค้ามาถึงโชว์รูม** | พนักงานกด "มาแล้ว" ในระบบ (มือถือ) · ใส่เบอร์โทร · ถ้าไม่มีรหัส ถาม "รู้จักเราจากไหน" แทน |
| 5 | ระบบส่งกลับให้โฆษณา | **Meta** → Conversions API event `ShowroomVisit` (`action_source: physical_store`) + fbclid + เบอร์ (hash) · **Google Ads** → offline conversion ด้วย gclid + เบอร์ (hash) |

### ผลที่ได้

| ตัวเลข | ได้จาก |
|---|---|
| คนเข้าหน้าโชว์รูม → กด LINE → **มาจริง** แยกรายแคมเปญ/โฆษณา | ระบบเรา (ตรงที่สุด) |
| **ต้นทุนต่อ 1 คนที่มาโชว์รูม** | ค่าโฆษณา ÷ คนมาจริง |
| Meta / Google เห็น "มาจริง" เป็น conversion | ตั้งให้โฆษณา**หาคนที่มาจริง** แทนคนที่แค่กด → โฆษณาคุ้มขึ้น |
| คนมาจากโฆษณาแต่ไม่ได้ผ่านหน้าเว็บ (ทัก LINE ตรงจากโพสต์) | Meta จับคู่จาก**เบอร์โทร**ได้บางส่วน · ส่วนที่เหลือได้จากคำถาม "รู้จักจากไหน" |

### ⚠️ ต้องรู้

- **เบอร์โทร** ส่งให้ Meta/Google แบบ hash เท่านั้น และต้องแจ้งลูกค้า (PDPA) · ใส่ในนโยบายความเป็นส่วนตัว + แถบคุกกี้
- **ไม่ได้ 100%** · คนเปลี่ยนข้อความ ลบรหัส หรือพาเพื่อนมา → คาดว่าจับได้ส่วนใหญ่ ส่วนที่หลุดเก็บจากคำถามหน้าโชว์รูม
- ต้องมี**ที่เก็บ** รหัสนัด + เช็กอิน → ใช้ตารางลูกค้าใน CRM เดิม (0032) เพิ่ม "นัด/การมาโชว์รูม" · ไม่ต้องทำระบบใหม่
- ขั้น 4 พนักงาน**ต้องกดจริงทุกครั้ง** ถ้าไม่กด ตัวเลขทั้งหมดใช้ไม่ได้ · ทำให้กดง่ายที่สุด (1 ปุ่ม + เบอร์)
