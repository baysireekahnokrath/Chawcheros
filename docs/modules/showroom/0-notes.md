## แผนการขึ้นใช้งาน (คิดไว้ก่อน ยังไม่ทำ)

```
แก้โค้ด → push ขึ้น branch
            │
            ▼
   Vercel สร้างเวอร์ชัน test อัตโนมัติ   (ลิงก์ test · มีแถบ "ทดสอบ" บนหน้าจอ)
            │
     Bay เปิดดูบนมือถือ · OK ไหม?
            │ OK
            ▼
   Bay กด "Promote to Production" ใน Vercel   ← ปุ่มเดียว
            │
            ▼
   os.chawcher.com/showroom   (พนักงานใช้จริง)
```

- ปิด "ขึ้น production อัตโนมัติ" ใน Vercel → **ไม่มีอะไรถึงมือพนักงานจนกว่า Bay จะกด** (ตรงกับกฎ "ห้าม deploy ก่อน Bay อนุมัติ")
- ปุ่มเดียวกันนี้ใช้ **ย้อนกลับเวอร์ชันก่อน** ได้ทันที ถ้าขึ้นไปแล้วมีปัญหา
- ใช้ Vercel โปรเจกต์ `chawcher-os` ที่มีอยู่แล้ว · โมดูลอื่นในอนาคตอยู่ใต้โดเมนเดียวกัน `os.chawcher.com/<module>`
- PWA: ตั้งให้ไอคอนบนหน้าจอโฮมเปิดตรงเข้า `/showroom` · เวอร์ชัน test ต้องดูต่างจากของจริงชัดๆ กันพนักงานกรอกข้อมูลลูกค้าจริงลงตัว test

### ⚠️ จุดที่ปุ่มเดียวยังไม่ครอบคลุม: ฐานข้อมูล

ปุ่ม Promote ย้ายแค่ **หน้าเว็บ** ไม่ได้ย้าย **โครงสร้างตาราง**
ถ้าเวอร์ชันใหม่เพิ่มช่องในตาราง ต้องอัปเดตฐานข้อมูลจริงก่อนหรือพร้อมกับการกดปุ่ม ไม่งั้นหน้าเว็บใหม่จะพัง

ตัวเลือกฐานข้อมูลฝั่ง test (ต้องให้ Bay เลือก):

| ทาง | ข้อดี | ข้อเสีย |
|---|---|---|
| 1. test ใช้ฐานข้อมูลจริงตัวเดียวกัน | ไม่มีค่าใช้จ่ายเพิ่ม | ข้อมูลทดสอบปนกับข้อมูลลูกค้าจริง · ทดสอบเปลี่ยนตารางไม่ได้ |
| 2. โปรเจกต์ Supabase แยกสำหรับ test | แยกขาดจากของจริง | ต้องให้ Bay อนุมัติสร้างโปรเจกต์ใหม่ · ต้องคอยทำโครงสร้างให้ตรงกันสองที่ |
| 3. Supabase Branching (ฐานข้อมูลสำเนาต่อ branch) | ผูกกับ test ของ Vercel อัตโนมัติ | ต้องใช้แพ็กเกจเสียเงิน |
