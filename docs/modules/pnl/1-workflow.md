## 3 · ระบบที่เสนอ · หน้าเดียว `/pnl` (แบบ E · รายงาน)

### โครง P&L (ต่อจาก J9)

```
ยอดขาย (รวม VAT)                 ← POS + ออเดอร์
  ÷ (1 + VAT)
= รายได้จริง
  − ต้นทุนสินค้า (ราคาโอน) 🔒
= กำไรขั้นต้น
  − ค่าใช้จ่ายขาย                 ← คอมมิชชัน · ค่าขนส่ง · ค่าธรรมเนียมช่องทาง/บัตร
= กำไรหลังค่าใช้จ่ายขาย
  − ค่าใช้จ่ายคงที่                ← โฆษณา · เงินเดือน · ค่าเช่า · อื่นๆ
= กำไรสุทธิ
```

### ข้อมูลมาจากไหน · ทำเป็น 3 ขั้น ใช้ได้ตั้งแต่ขั้นแรก

| ขั้น | ได้อะไร | ข้อมูล | คนต้องทำอะไรเพิ่ม |
|---|---|---|---|
| **ก · รายได้สด** | ยอดขาย · รายได้จริง แยกช่องทาง แยกวัน | POS (สด) + ดึงช่องเงินจากชีต (ปรับซิงก์ให้ถี่ขึ้น + ปุ่ม "ดึงตอนนี้") | ไม่มี |
| **ข · กำไรระดับเดือน** | กำไรขั้นต้น · กำไรสุทธิ รายเดือน | Bay กรอก**เดือนละครั้ง**: ยอดซื้อจาก ASE + ค่าใช้จ่ายคงที่ 4-5 บรรทัด · ค่าธรรมเนียมช่องทางตั้งเป็น % ครั้งเดียว | Bay ~5 นาที/เดือน |
| **ค · กำไรรายออเดอร์** | กำไรต่อออเดอร์ ต่อรุ่น ต่อเซลส์ | ออเดอร์คีย์ในระบบ (มีรหัสสินค้า) × `cost.v_variant_cost` | รอโมดูลออเดอร์ใช้จริง (Phase 2) + ราคาโอนครบ |

**ทุกตัวเลขบอกความมั่นใจ** เหมือนโมดูลต้นทุน (§1.4): ป้าย "จริง" / "ประมาณ" / "ยังไม่มีข้อมูล" + บอกว่าต้นทุนครอบคลุมกี่ % ของยอดขาย · ไม่แสร้งว่าแม่น

### สิ่งที่ตั้งใจไม่ทำ

- ไม่ดึงช่อง `ต้นทุน` จากชีต (ว่างอยู่แล้ว และขัดหลัก O2)
- ไม่เขียนกลับชีต (B40)
- ไม่ใช่ระบบบัญชี · ไม่แทนงบของสำนักงานบัญชี · เป็นตัวเลขบริหาร
- ไม่ส่งตัวเลขนี้เข้า LINE ทุกกรณี
