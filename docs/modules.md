# ระบบโมดูล — อ่านแบบไม่ต้องเป็นโปรแกรมเมอร์

> เขียนตามที่ Bay ขอว่า *"เป็น module เหมือนพวก salesforce.com"*

---

## โมดูลคืออะไรในระบบนี้

**1 โมดูล = 1 ก้อนงานที่พังเองได้ ซ่อมเองได้ ปิดเองได้ โดยไม่ลากตัวอื่นพังไปด้วย**

เหมือน Salesforce ที่มี Sales Cloud / Service Cloud / Marketing Cloud แยกกัน
เปิดใช้เฉพาะที่ต้องการ และอัปเกรดทีละตัวได้

---

## ตอนนี้มีโมดูลอะไรบ้าง

| โมดูล | เก็บอะไร | ปิดได้ไหม |
|---|---|---|
| ⚙️ **ตั้งค่าระบบ** | ผู้ใช้ · สิทธิ์ · ประวัติการแก้ · ทะเบียนโมดูล | ❌ ปิดไม่ได้ |
| 📦 **สินค้า** | รุ่น · ตัวที่ขายจริง · SKU | ❌ มีคนพึ่งอยู่ |
| 🎨 **คลังผ้า** | ผ้า · หนัง · ป้อนหน้าเว็บ material-list | ✅ |
| 🏷️ **ราคา** | ราคาตั้ง · ส่วนลดปกติ · ส่วนลดขั้นบันได | ❌ มีคนพึ่งอยู่ |
| 🔒 **ต้นทุน** | ต้นทุนและกำไร (เจ้าของเท่านั้น) | ✅ |

**ที่จะมาต่อ:** สต็อก · จัดซื้อ · ลูกค้า · ขาย · จัดส่ง · ผลิต · การตลาด · กราฟิก · การเงิน · ชั้น AI

---

## 3 อย่างที่ได้จากการทำเป็นโมดูล

### 1. พังทีละก้อน ไม่พังทั้งระบบ

ถ้าโมดูลคลังผ้ามีปัญหา → สินค้า ราคา ต้นทุน **ยังใช้ได้ปกติ**
และเวลาซ่อม ก็ซ่อมแค่ก้อนนั้น ไม่ต้องแตะอย่างอื่นเลย

### 2. เปิด/ปิดได้ โดยไม่ต้องรื้อโค้ด

ปิดโมดูลไหน → **หายจากเมนูทันที ข้อมูลยังอยู่ครบ** เปิดกลับมาเมื่อไหร่ก็ได้
เหมาะกับการค่อยๆ เปิดใช้ทีละแผนก ไม่ต้องเปิดพร้อมกันหมด

**ระบบกันไว้แล้ว 2 ชั้น:**
- ปิดโมดูล "ตั้งค่าระบบ" ไม่ได้ — ปิดแล้วพังหมด
- ปิดโมดูลที่คนอื่นพึ่งอยู่ไม่ได้ — ระบบจะบอกว่าใครพึ่งอยู่บ้าง

### 3. เมนูสร้างตัวเอง

เมนูและหน้ารวมแอป (App Launcher) **อ่านจากทะเบียนโมดูลโดยตรง**
เพิ่มโมดูลใหม่ = เพิ่ม 1 แถวในทะเบียน **ไม่ต้องไปตามแก้เมนูที่ไหนเลย**

## กฎที่ทำให้มันเป็นโมดูลจริง ไม่ใช่แค่จัดโฟลเดอร์สวย

> **โมดูลหนึ่ง ห้ามแตะข้อมูลของอีกโมดูลโดยตรง
> ต้องเรียกผ่าน "ประตู" ที่โมดูลนั้นเปิดไว้ให้เท่านั้น**

ตัวอย่าง — ตอนออก PO ต้องจองของ:

| | เกิดอะไรขึ้นตอนกฎเปลี่ยน |
|---|---|
| ❌ ขายเขียนตรงเข้าตารางสต็อก | พี่บอกว่า "ของตำหนิห้ามจอง" → ต้องไล่หาทุกที่ที่เคยเขียน **พลาดที่เดียวก็บั๊ก** |
| ✅ ขายเรียกประตูของสต็อก | แก้ในประตูเดียว **ทุกคนได้กฎใหม่พร้อมกันทันที** |

**และกฎนี้ฐานข้อมูลบังคับเอง** — ไม่ได้ให้สิทธิ์ข้ามโมดูล ใครแอบเขียนตรงจะ error ทันที
ไม่ใช่กฎที่เขียนไว้ในเอกสารแล้วหวังว่าคนจะทำตาม

---

## ลำดับการพึ่งพา — ห้ามวนกลับ

```
ตั้งค่าระบบ ──► สินค้า ──► ราคา ──► ต้นทุน 🔒
     └────────► คลังผ้า
```

ลูกศรชี้ไป = พึ่งพา · **ถ้าวันไหนมีลูกศรวนกลับ แปลว่าออกแบบผิด**
เพราะพอวนกลับแล้ว จะแยกกันพังไม่ได้อีกต่อไป

---

## เรื่องที่คนมักเข้าใจผิด

**"ถ้าสต็อกพัง แล้วขายยังขายได้ไหม"** → **ไม่ได้**

แต่นั่น**ไม่ใช่ความผิดของการออกแบบ** — Bay ยืนยันเองว่า *"ออก PO แล้วของถูกจองทันที"*
ถ้าจองของไม่ได้ ก็ออก PO ไม่ได้ **นี่คือกฎธุรกิจ ไม่ใช่ข้อจำกัดทางเทคนิค**

โมดูลช่วยให้ **"ซ่อมทีละก้อน"** ได้ แต่ช่วยให้ **"ทำงานได้ทั้งที่ของจำเป็นหายไป"** ไม่ได้

## ⚠️ สำหรับคนที่มาทำต่อ

**เพิ่มโมดูลใหม่ ต้องทำ 3 อย่าง ห้ามลืมข้อไหน:**

1. สร้าง schema ใหม่ + ตารางในนั้น
2. เพิ่ม 1 แถวใน `core.modules` (ชื่อ ไอคอน พึ่งใคร สิทธิ์อะไร)
3. **เติมชื่อ schema ใน `0009_expose_module_schemas.sql`**
   ← ลืมข้อนี้ = โมดูลสร้างเสร็จแต่เว็บเรียกไม่ได้ และหาสาเหตุยากมาก
